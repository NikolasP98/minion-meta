# Roll the generated labeler configs out to the fleet

Follow-up to slice 8 of `specs/2026-08-17-sdlc-phase-gates-scoring-spec.md` (§4b),
which landed the taxonomy in minion-meta only. This proposal carries the open ends
that slice deliberately left, so they are written down rather than assumed.

## AS-IS (verified in this repo, 2026-08-20)

- `routing.yml` declares the 9-value tag enum and per-repo glob → tag rules for all
  9 fleet repos; `scripts/routing.mjs validate` gates it, `scripts/routing.test.mjs`
  covers the glob dialect, the derivation and the CLI.
- `scripts/spec-index.mjs` and `scripts/proposal-index.mjs` reject an unknown tag
  and a scalar (unbracketed) `tags` value. Proven red-before/green-after against the
  pre-change script.
- `generated/labeler/<repo-id>.yml` and `<repo-id>.workflow.yml` are written for every
  fleet repo, and **the rollout is done**: `pnpm run routing:verify-remote` exits 0
  (2026-08-20). minion-meta consumes its own pair from `.github/` (regenerated by
  `pnpm run routing:generate`, drift-gated by `routing:validate`); the blocks and, where
  none existed, the workflow were written to `minion minion_hub minion_site
  minion_plugins paperclip minion-factory minion-base` on their configured PR base over
  the GitHub contents API. The gateway kept its own labeler workflow (it already
  satisfied the contract) and all 45 of its `channel:/app:/extensions:` topic labels.
  `pixel-agents` is the one repo left, and it is **blocked, not skipped**: its remote is
  the third-party `pixel-agents-hq/pixel-agents` (configured as `pablodelucca/…`) where
  this org has no push access and contributes by fork PR, so `routing.yml` declares
  `externalUpstream` on it and the gate prints the reason instead of a silent pass.
- Pasting a generated block next to a repo's own labels is only safe while the two
  vocabularies are **disjoint**. The gateway already had a topic label literally named
  `docs`; appending ours made a duplicate top-level YAML key, which js-yaml — what
  `actions/labeler` parses with — rejects outright, so the labeler would have applied
  *nothing* on every gateway PR. Its `docs.acp.md` glob now lives in `routing.yml`, the
  generated `docs` block is a strict superset of what it replaced, and
  `duplicateLabelerKeys` in `scripts/routing.mjs` makes the collision a verifier finding
  rather than a silent outage.
- `routing.yml`'s `legacyTags` allowlist still carries 8 pre-taxonomy values
  (`handoff-sweep`, `edge-case`, `unwired`, `hardcoded`, `todo`, `duplication`,
  `board`, `ux`) used by 37 tag occurrences across 36 cards — all of them proposals
  now that the four handoff specs below are retagged. `crm` was the ninth and is
  deleted: its only carrier was a spec, and the validator fails on an allowlist entry
  that has gone unused. The factory's handoff sweep keeps writing
  `tags: [handoff-sweep]` on proposals, so that entry cannot expire on its own.
- Spec **slice-level** tags are now machine truth: `slice_tags: [1:logic+test, 2:ui]`
  in spec frontmatter, validated by `scripts/spec-index.mjs` and `routing:validate`
  (unknown/legacy/duplicate/out-of-order tags, gaps in the 1..N numbering, disagreement
  with the spec-level `tags` union, a legacy top-level tag next to that union, and a
  row-count mismatch against a `| # | Slice | … |` table all fail).
  `sliceTagsRequiredFrom` was fixed from a future date (2026-08-21, one day after this
  taxonomy actually landed) to the taxonomy's real landing day (2026-08-20) — a future
  cutoff exempted same-day work from the gate it was meant to enforce. Every executable
  same-day spec that landed under that bug is now retro-tagged: `2026-08-20-handoff-minion-hub-2785164896-spec`,
  `-3530856808-spec`, `-2131866440-spec`, `-1323254565-spec` and
  `2026-08-20-handoff-minion-factory-1487584490-spec` (five, found by re-running the gate
  against the merged `dev` tree — a branch-local run does not see base-only additions).
  Two fail-open holes in the cutoff itself are closed with it: a non-ISO `created`
  ("today") and an impossible cutoff date (`2026-13-01`, which sorts above every real
  `created` under the lexicographic compare) now both mean "required", not "exempt".
  Required for specs created on or after `sliceTagsRequiredFrom`; the ~56 executable
  specs written before it (2026-07-19 through 2026-08-19) remain exempt until they
  are retro-tagged. The `TODO(handoff):` marker in `scripts/routing.mjs` is gone with
  the rollout it tracked; no open end remains in that file.
- `slice_tags` entries are parsed against `<tag>[+<tag>…]` proper: the previous
  `[a-z0-9+-]+` payload accepted `1:+logic`, `1:logic+` and `1:logic++test`, then
  filtered the empty positions away, so a malformed string passed the fail-closed gate
  and shipped verbatim into `specs/index.json`. All three positions have negative
  fixtures.

## Rollout note (the gate that can break another repo's bot)

From `sliceTagsRequiredFrom` on, a spec written without `slice_tags` fails
`scripts/spec-index.mjs` — and the factory runs that script when it commits
`index: … [auto-triage]`. The spec agent follows `specs/TEMPLATE.md`, which now
documents the field, so the fix for a red sweep is to add the line the error names,
never to relax the gate: an untagged slice is a dev run that cannot pick its checks.

The same gate now also rejects a legacy top-level tag on a spec that must carry
`slice_tags`. The handoff sweep writes `tags: [handoff-sweep, …]` on the **proposal**,
and the spec agent has been copying that list onto the spec it derives — that copy is
what fails. The fix is again the one the error names: tag the spec with the union of its
slices' work types and leave `handoff-sweep` on the proposal, which is the card whose
source it actually records. Relaxing the rule would let the legacy ledger grow on new
work, which is the opposite of the ratchet it is supposed to be.

## Out of scope

Changing the taxonomy itself, the gate rubrics (slices 1–7, 9, 10 of the phase-gates
spec), and any board rendering of tags.

## Definition of done

`pnpm run routing:verify-remote` exits 0 with no `externalUpstream` declarations left, a
live labeler run has applied the derived labels on a real PR in each fleet repo,
`routing.yml`'s `legacyTags` is empty, and `sliceTagsRequiredFrom` covers every
executable spec.

# Technical prose

## Pick one mode

- **Tutorial:** teach by building; produce visible results early and state expected output.
- **How-to:** give competent readers the shortest path to a goal; move background elsewhere.
- **Reference:** state complete lookup facts and mirror the structure of the thing described.
- **Explanation:** answer one bounded why question with context, constraints, and trade-offs.

Split and link rather than mixing modes in one section.

## Write for first-pass understanding

- Address the reader as `you`; use present tense and active actors.
- Write instructions as commands. Put the applicable condition first.
- Put the common case before exceptions.
- Prefer short everyday words, but keep the precise domain term and exact code name.
- Cut words that add no fact, action, condition, or distinction.
- Keep pronouns tied to one obvious noun. Repeat the noun when needed.
- Keep `only`, negation, and scope words next to what they modify.
- Break ambiguous noun stacks into clauses.
- Use numbered lists for sequences and bullets for unordered peers. Keep list items parallel.
- Use descriptive link text, sentence-case headings, one H1, and unskipped heading levels.
- Vary sentence length without creating clipped staccato prose.

Avoid invented jargon, empty abstraction, idioms, and claims that a procedure is easy. Specific evidence beats sterile generality: name the command, field, failure, or observed result.

## Review

Confirm that each command is executable as printed, each symbol and path exists, each expected result is current, and each changed sentence preserves certainty, attribution, quantities, and conditions.

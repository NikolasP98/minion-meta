- Each real profile and each separate decode launch: maximum 60 seconds, 2048MiB V8 old-space; no higher-budget retry. These are not an OS RSS ceiling. Synthetic fixtures use shorter 1–5 second bounds and small inputs, with the exact selected installed runtime/nft.
- Raw profiler stream: at most 16MiB persisted by the parent, enforced while consuming chunks; retain only the permitted prefix, immediately terminate the owned process group at exhaustion and label `profile-budget-exhausted`. No uncapped native profiler file is written by the child. Existing worker evidence has a separate maximum 8MiB; profile-mode output accounting permits their 24MiB combined maximum. Separate input inventories/control records retain their existing 32/64MiB bounds.
- Profile-mode stderr: bounded control/diagnostic channel, maximum 64KiB, with overflow an explicit failure. A malformed or truncated admission message never authorizes analysis. Ordinary nonprofile mode must retain existing behavior.
- Decoder output: maximum 4MiB persisted stdout and 64KiB diagnostic stderr, with overflow/timeout explicit. No unbounded buffered subprocess output. Its raw profile input is a previously bounded, hash-verified regular file, at most 16MiB.
- Hash and preserve the original captured profile bytes. If the final log record is incomplete, derive only a complete-newline prefix for the built-in decoder, recording original/derived lengths/hashes and discarded tail bytes. Never invent missing code/tick records or rewrite the raw evidence. If dropped/unflushed records prevent interpretation, report that failure.
- The target 1ms statistical interval is not a guaranteed sample rate. Include startup/probe overhead, sampled window, unaccounted/unknown ticks, absent native symbols and profiler overhead. Do not treat sample percentages as wall-time phase measurements or use the known defective reaper RSS field for conclusions. Worker-RSS repair is not required by this CPU-only plan and remains in the proposal ledger.

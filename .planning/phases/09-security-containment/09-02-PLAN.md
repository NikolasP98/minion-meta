## Constraints and design

- Node22 currently lacks DatabaseSync.setAuthorizer. Use a separate readOnly:true connection, closed in finally; never mutate PRAGMA query_only on the shared writer.
- Existing SELECT/WITH prefix restriction remains an API surface restriction (blocks standalone ATTACH/PRAGMA), not the security proof. CTE writes must fail in SQLite itself. Compare prepared statement.sourceSQL to full input to reject trailing statements without writing a SQL parser.
- Existing explicit consume-marker is retained as a distinct write after successful read, with validated identifiers and same caller capability. This does not grant a new read-only role or claim the combined operation has no writes. Caller authority propagation remains A9 in the existing remediation proposal.
- Existing gateway config.params positional-array protocol is retained. Add an optional typed node params field; replace only an entire `{input}` binding value. SQL containing legacy `{input}` is rejected with a migration message, not guessed/reparsed. Scalars must fit JSON/SQLite: string, finite number, null. Booleans must be modeled explicitly as 0/1 by authors.
- No saved-flow or production data migration in this slice. Existing definitions using SQL interpolation require reviewed conversion before this compiler is deployed. No UI changes, provider calls, release, branch or stash operations.
- Preserve the pre-existing handoff comments except the directly resolved A1/A2 portions. Retain A9.

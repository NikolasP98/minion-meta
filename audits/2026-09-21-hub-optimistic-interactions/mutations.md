## Behavioral contract proposed for the spec

1. Classify each interaction as local presentation, reversible entity mutation, coherent form submission, external/business command, or long-running job. The class determines optimism, confirmation, retry, and undo; the HTTP verb alone does not.
2. Respond locally in the interaction frame: focus, selection, drag position, pending overlay, or queued bubble. This is visual acknowledgement, not a claim of server success. Leave unrelated controls usable; block or queue only conflicting operations.
3. Capture org, user, server, entity, operation ID, submitted patch, and base revision before awaiting work. Responses may update only that scope and revision. Teardown/org switches remove subscriptions and quarantine pending work from the next scope.
4. Layer pending intent over canonical state. Apply rollback to the rejected operation's patch only; never restore an obsolete whole-list snapshot over unrelated successful edits. Keep authored text when errors/conflicts occur.
5. Serialize writes per entity or use proven operation/revision ordering. Debounce text edits with a bounded wait and explicit blur/Enter semantics. Handle IME composition; do not commit partial composition. A success for revision N cannot clear revision N+1.
6. Retry only with established semantics. Reuse idempotency identity for an external command; use expected-version preconditions for entity updates. On uncertain delivery, reconcile first. Cancellation of a request is not reversal of a server mutation.
7. Publish committed entity signals through existing org realtime, then refresh authorized canonical data. Adapt SvelteKit dependencies, client query keys, and specialized caches separately. Protect active drafts when server changes arrive.
8. Expose saving/saved/error/conflict and accepted/running/completed as distinct accessible states. Do not show success toast for every keystroke. Keep errors visible near the affected field with retry/review actions.
9. Motion should communicate the local action: preserve keyed rows/bubbles and focus, animate insertion/reorder rather than remounting whole views, reserve pending status space, and avoid layout shifts during refetch. Reduced-motion users receive equivalent immediate state and textual status. Exact tokens/timings belong to the shared motion specification; this source audit supplies no measured latency budget.
10. Save-less editing does not remove explicit Send, Submit, Cancel posting, Disconnect, Publish shared default, or other meaningful business commitments. Give these immediate pending feedback while awaiting authoritative outcome.

## Qualification requirements

| Test | Required result |
| --- | --- |
| Overlapping same-key optimistic operations | Earlier settlement cannot delete newer overlay or roll back newer intent. |
| Debounced edit during in-flight save | New draft survives acknowledgement and is subsequently committed; no premature saved state. |
| Conflict and HTTP rejection | No false success; typed errors, draft preservation, atomic stale-write rejection. |
| Timed-out external command | Reuse operation ID/reconcile outcome; no duplicate message, ledger entry, or job. |
| Partial group move failure | Server and UI converge; source membership is not falsely restored only in cache. |
| Create then edit/delete before acknowledgement | Temp/server ID reconciliation preserves latest intent and stable DOM identity. |
| Failed note creation plus reload | Authored draft remains recoverable in intended scope; retry does not duplicate server record. |
| Dashboard changed during shared-default PUT | Cache reflects acknowledged snapshot, not later unsent local layout. |
| Host/org/user switch during mutation | No response, overlay, draft, or cache entry leaks into new scope. |
| Realtime update during local draft | Remote canonical state refreshes without clobbering draft; conflict is explicit. |
| Reconnect, visibility regain, duplicate events | Bounded refetch, eventual convergence, no duplicate optimistic objects. |
| Keyboard, IME, reduced motion, focus | Equivalent outcomes and accessible status; no focus loss/remount on acknowledgement. |

These tests are proposed qualification gates. None were executed in this audit. Existing sources establish implementation patterns and risks, not proof of deployed behavior or complete backend idempotency guarantees.

One action service.
Several honest views of its status.

Recommended: a typed action runtime with reactive signals, local pending feedback and a quiet global activity indicator. Build on the coordinator already specified.

Track the intent once

Action definition → runtime/coordinator → domain adapter → HTTP / RPC / job

Reactive state → local field status + global activity + optional details

“Move appointment” is one action. Its PATCH, three refreshes and retry attempts are children. A successful PATCH followed by a failed refresh stays committed—never falsely rolled back.

Proposed global activity behavior

Interactive simulation only. Start multiple operations to see why a single boolean or raw request counter is insufficient. No backend requests are made.

No foreground work0 background jobs 0 need attention

No active actions

The spinner appears after 150 ms. Jobs transfer to their badge after acceptance; a lost response becomes an attention item. Neither leaves the main spinner running forever.

Foreground activity

Navigation, requested reads and pending saves. Nonblocking; count logical actions, not each endpoint.

Background work

Accepted jobs have progress/stages. Polling, prefetches and open sockets do not make the whole app busy.

Needs attention

Failures, conflicts and unknown outcomes stay actionable. An idle spinner never means every change is saved.

Use signals over authoritative state

  • Reuse Svelte 5 reactive state and derived selectors; no new signals library is needed.
  • The runtime validates a transition, updates its record, then emits a typed notification.
  • A subscriber mounting later reads the snapshot. Missing a past “started” signal cannot leave it stuck.
  • Observers do not issue arbitrary writes or retries. Dependencies and recovery belong to the declared action pipeline.

Evaluate the implementation choices

Fetch interceptor

Useful for diagnostics. Misses non-HTTP lifecycles and cannot infer business success. Polls would keep it noisy.

Query counters

Useful adapter where QueryClient is already used. Hub intentionally also uses SvelteKit loads and gateway push state.

Typed action runtime

Recommended. One root action owns attempts, refreshes and job handoff, with scope-aware reactive selectors.

Build the small API first

  1. Code-authored definitions name the action, validated input, policy, scope, adapter and concurrency key.
  2. The application runtime runs them and exposes typed outcome/status; the builder itself has no side effects.
  3. Connect the existing top navigation/connection bar, one safe action and one job adapter.
  4. Grow into composed actions only after partial failure, cancellation and compensation are defined. A sequence of endpoints is not a transaction.

Keep it efficient

Update normalized records on state changes, with small aggregate counters and scoped subscriptions. Throttle progress; never register each stream token or animation frame. Bound completed history, keep unresolved operation identity recoverable and use explicit parent IDs to prevent nested double counting.

Runtime is per browser app and per request on SSR. Scope captures org/user/host at dispatch; old replies cannot affect a newly selected organization.

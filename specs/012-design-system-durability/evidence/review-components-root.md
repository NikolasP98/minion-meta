## Findings

### M1 — PartyPicker quick-add dirty flag is module-level state shared by every instance
- `src/lib/components/crm/PartyPicker.svelte:3` — `let createDirty = $state(false);` sits inside `<script lang="ts" module>`; `bind:dirty={createDirty}` (l.244) and `{createDirty}` (l.336) therefore read/write ONE variable for all mounted PartyPickers. `StockItemPicker.svelte:78` does it correctly in the instance script.
- Scenario: `routes/(app)/workforce/projects/+page.svelte` mounts two PartyPickers (floating windows, both can be open). Type in picker A's create form → shared flag true → closing picker B's untouched create tab prompts "discard". Worse: B's form `$effect` later recomputes the shared flag to `false` → closing A with typed data no longer prompts → silent loss of the draft the dirty guard exists to protect.
- Fix: move the declaration into the instance `<script>` (1 line).

### M2 — Daily dashboard: a local scoped layout permanently shadows the server section (cross-device follow regressed, same org)
- `routes/(app)/notifications/daily/+page.svelte:66` — `createScopedPreference('dailyDashboard', () => normalize(stored), normalize)`: `stored` (the `/api/me/preferences` value from `page.data`) is consulted ONLY as the fallback when no local key exists (`scoped-preference.svelte.ts:25`). Once a device has written the local key, server changes made elsewhere are never applied; the "Use saved layout" button (l.272–277) only renders after an UNCERTAIN write followed by Reconcile (`saveState === 'checked' && canUseCanonical`).
- Scenario: user arranges cards on laptop → server updated (409/org guard fine). Phone, which arranged earlier, keeps its local layout forever; the removed header comment "so the layout follows them across devices" described the prior behaviour. The handover documents the *cross-org* limitation (server keeps last org only) as approved, not this same-org shadowing.
- Fix (small): when `stored.organizationId === activeOrgId` and `JSON(normalize(stored)) !== JSON(local.value)`, either prefer the server value at mount (server is the per-user source of truth per governance "prefs that follow the user = /api/me/preferences") or render the existing "Use saved layout" button in that state too (`local.set(normalize(stored))`, no write).

### M3 — CRT/voxelized decorative selectors were narrowed to `data-part` hooks that nothing emits
- `src/app.css` (voxelized F/G/M/N blocks, crt I/J/N blocks): `[data-part='dialog']`, `[data-part='panel']`, `[data-part='navigation']`, `[data-part='status-dot'][data-status='success']` — grep over `src/**/*.svelte` and the installed `node_modules/@minion-stack/ui/dist` finds 0 emitters for all four (`page-header` has 1, `card` 1 in dist, `section-shell` 1). The dialog glow/radius, panel gradient, nav radius and success-dot glow are now dead CSS in both decorative themes.
- Scenario: `?decoration=crt` fixture or a user on the CRT theme loses the header-adjacent nav/panel/dialog treatment silently; design-lint still counts the raw rgba in these dead rules as debt.
- Fix: emit the hooks on `Dialog.svelte` content (`data-part="dialog"`), `SectionNav`/sidebar nav (`navigation`), the card/panel surfaces that previously matched `[class*='panel']`, and the status dot; or delete the dead rules and state so in `foundations-implementation.md`. Decorative-only, so not blocking.

### L1 — `onRowActivate` silently disables spreadsheet cell selection/editing and Space-select
- `DataTable.svelte` `onCellPointerDown` (new first line): `if (!gridMode || onRowActivate || interactiveTarget(e.target)) return;` — any table that passes `onRowActivate` loses pointer cell selection, range copy and the click-to-edit entry; the Space hotkey is disabled by `!onRowActivate` while `onGridKeydown` only handles Space when `!selectable`, so a selectable + activatable table has no keyboard row toggle. Current callers (Picker, Recipes) are read-only so nothing regresses today; the prop doc ("single click remains separate") does not say this.
- Fix: document the coupling on the prop, or gate the early return on "no editable column" instead of on `onRowActivate`.

### L2 — DataTable `persist()` emits a warning toast on EVERY column mutation when storage is unavailable
- `DataTable.svelte` `persist()`: `toastWarning(m.design_local_only())` both when `layoutStorageKey` is null (no actor/org — e.g. the empty-org QA persona) and on a `setItem` throw. Each resize/hide/reorder/aggregate change spawns another toast; governance asks for a bounded recovery state.
- Fix: toast once per mount (flag) or render a status line like EditableGrid's `eg-status`.

### L3 — FieldsList keyboard move returns focus to the row's visibility toggle, not the arrow that was pressed
- `FieldsList.svelte:61-63` focuses `.hc-field-btn` after `move()`. A keyboard user pressing Enter twice on "Move later" hides the field on the second press.
- Fix: focus the same arrow (`[data-field-key=…] .hc-move button:nth-child(1|2)`), falling back to the toggle only when the arrow became disabled.

### L4 — SecretsSection shows "result is uncertain / retry disabled" for a clear that was never sent
- `SecretsSection.svelte` `confirmClear()`: when `target.owner !== secretOwner()` or `!conn.connected` it sets `clearUnknown = true` and throws BEFORE `sendRequest`. `ConfirmDialog` then renders `design_mutation_unknown_review` with `retryable=false`, although no write happened. Same shape in `ChannelsTab.confirmDelete` ("Scope changed" → `deleteUnknown = true`).
- Fix: throw a plain (retryable) error for scope/connection changes; reserve `unknown` for a dispatched request without receipt.

### L5 — Live announcements read the command label, not the outcome
- `EditableGrid.svelte:242-246` announces `design_hide({label})` ("Hide X") after hiding; `FieldsList.svelte:56-59` announces "Move X earlier" after moving. Screen-reader users hear an instruction, not a state. Minor copy; add outcome strings ("X hidden", "X moved to position N").

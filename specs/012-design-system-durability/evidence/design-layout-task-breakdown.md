## Scope clarifications for review

- Grid hide/show needs optional hidden IDs because current GridLayout has no hidden state, yet UI contract explicitly includes it. Editing mode must expose hidden cards so users can recover visibility; normal mode omits hidden items. Reset removes only current scope preference.
- API accepts bounded structural grid layouts; catalogs are route-defined, so server cannot validate every catalog ID without a new registry. Client intersects known catalog; parser prevents prototype-key hazards and unbounded data.
- Catalog rename support means explicit aliases supplied by caller only, no guessing based on label/position.
- Read-only table vs editing grid must be based on interaction capability, not canEdit alone: current tables allow cell selection/copy even without editable columns. Define coherent focus through aria-activedescendant only on cells actually mounted; row virtualization must invalidate stale active IDs.
- Remote preference write transport failure may be unknown (not definite rejected). Recovery first reads canonical preferences; do not advertise blind retry as generic safe behavior. Daily local-only preference can remain usable without claiming server persistence.

## Composition pilot decision

Existing POS collection already composes `PageShell(archetype=collection, scroll=region) → DataView → PageHeader → EmptyState/BoardView/DataTable` at `routes/(app)/pos/catalog/+page.svelte:475+`. Scheduling calendar already uses PageShell + PageHeader + DataView with table/board alternate toolbar and calendar-specific toolbar at `routes/(app)/scheduling/calendar/+page.svelte:328+`. These have deliberately different switcher placement. **No source evidence yet warrants a new DataViewShell.** Build executable pilots/fixtures for these exact two compositions, assert one scroll owner, container shrink, toolbar reachability, empty/error/loading/read-only states. Document placement decisions through existing shell APIs. Add shell only if runtime pilots reveal the same missing responsibility in both.

## Existing strengths and tests to preserve

- `dashboard-layout-cache.ts` already scopes org defaults by org/dashboard and coalesces in flight.
- BoardView has keyboard/tap Move menu, focus restoration and live announcement; reuse its interaction vocabulary.
- DataTable already has mounted tests, preset tests for plain/resizable, chrome false override and explicit height. Extend missing configuration interactions, do not duplicate these tests or extract all options into a new framework.
- Calendar staff setter intentionally persists its argument instead of reactive state to avoid an effect loop; retain this regression test.
- Field overrides intersect allowed visible fields with organization rules elsewhere; no user preference may grant hidden privileged fields.
- Picker already owns one toggle policy for single/multi/duplicate/removal; move gesture ownership only, preserving that policy.

## 1. Identity

"NextERP" is ambiguous on GitHub. Candidates: `adexh/NextERP` (Next.js toy, 4★, dead 2024), `zakirkun/next-erp` (Laravel/Filament, 25★, HR = Employee CRUD only; attendance/leave "planned"), `tyy130/next-erp` (1★, no HR), `SchreinereiReinhardt/NextERP` (Nextcloud PHP). The only one with a real HR/HRMS module is the **ERPNext rebrand**: `AltFl0w/NextERP-Deployment` sets `ERPNEXT_REPO_URL=https://github.com/AltFl0w/NextERP.git` and points setup at `frappe/erpnext`. So the HR module is **`frappe/hrms`** (Employee/Department/Designation/Holiday List live in `frappe/erpnext`).

- Repo: https://github.com/frappe/hrms — GPL-3.0, Python (Frappe framework: DocType JSON + Python controllers, Vue PWA in `frontend/`), default branch `develop`, pushed 2026-09-01, 8,712★.

## 3. Workflows & rules

- **Leave status machine** (`leave_application.py`): draft with `status=Open`; approver sets Approved/Rejected; `on_submit` throws unless status ∈ {Approved, Rejected}; submit → `docstatus=1`; cancel → `docstatus=2` (Cancelled, ledger reversed, attendance cancelled). `validate()` runs `validate_active_employee`, `validate_dates`, `validate_balance_leaves`, `validate_leave_overlap` (employee, status in Open/Approved, ranges intersect; half-day-same-date exception), `validate_max_days`, block days, `validate_for_self_approval` (HR Settings `prevent_self_leave_approval`), `validate_applicable_after` (Leave Type.applicable_after days since joining = probation gate). Approver doc-sharing via `share_doc_with_approver` (`hrms/hr/utils.py`); approver = employee.leave_approver → department leave_approvers.
- **Balance** is ledger-based: `get_leave_allocation_records` sums ledger rows of type Leave Allocation/Adjustment (cf vs new); `get_leaves_for_period` sums Leave Application rows (negative); `get_remaining_leaves`: `leave_balance = total_allocated + leaves_taken(neg) + manually_expired`; `leave_balance_for_consumption = min(balance, days until allocation.to_date)`. `get_leave_details` also returns `leaves_pending_approval` = SUM(total_leave_days) where status=Open and `expired_leaves = total − (remaining + taken)`. Carry-forward capped by `maximum_carry_forwarded_leaves`; `expire_allocation` writes a negative `is_expired=1` ledger row.
- **Day counting** `get_number_of_leave_days`: `date_diff+1`, −0.5 for a valid half day, minus holidays unless `Leave Type.include_holiday`; applying only on holidays throws.
- **Holiday list vs weekly off**: weekly offs are *materialised* as Holiday rows with `weekly_off=1` by `get_weekly_off_dates()` (`holiday_list.py`), so one table answers `is_holiday()`. Resolution `get_holiday_list_for_employee` (employee.py): employee.holiday_list → company.default_holiday_list, hook-overridable (HRMS `holiday_list_assignment`).
- **Shifts → expected hours**: `get_employee_shift` (shift_assignment.py) = active submitted assignment covering the date, else `Employee.default_shift`; `get_shift_details` yields start/end datetime plus `actual_start/end` widened by check-in/out margins; midnight-spanning shifts handled in `get_shift_timings`; `has_overlapping_timings` blocks overlapping assignments. `ShiftScheduleAssignment.create_shifts()` expands weekly `repeat_on_days` into contiguous Shift Assignments (90-day horizon) from scheduler `process_auto_shift_creation`.
- **Attendance**: one record per employee/day (`validate_duplicate_record`), not before joining, not for Inactive; `check_leave_record` auto-sets On Leave/Half Day from an approved application. Auto-attendance (`shift_type.py` `get_attendance`): working_hours from check-ins → Absent if `< working_hours_threshold_for_absent`, Half Day if `< ..._half_day`, else Present; late/early via grace periods; `mark_absent_for_dates_with_no_attendance` skips holidays.
- **Lifecycle** (`employee.py`): `validate_status` requires `relieving_date` for Left and refuses if Active employees still `reports_to` them; `validate_date` orders DOB ≤ joining ≤ retirement/relieving/contract_end; `update_user_status` disables the linked User when not Active; `validate_active_employee` blocks all transactions for Inactive. Probation = `scheduled_confirmation_date`/`final_confirmation_date` + Leave Type `applicable_after`.

## 4. Clinic MVP (5–15 staff)

**MVP**: Employee (name, status, designation/role, joining, relieving_date, user link, `default_shift`, `holiday_list`, `leave_approver`); flat Designation; Shift Type (start/end, color); Shift Assignment (employee, shift, start/end, Active) + Shift Schedule weekly `repeat_on_days` expansion; Holiday List with materialised weekly offs; Leave Type (name, include_holiday, is_lwp, carry-forward flag); Leave Allocation (period + total); Leave Application (Open→Approved/Rejected, half_day, overlap check, balance = allocated − approved − pending); staff→bookable resource = a `resource_id` on Employee (no HRMS analogue; ERPNext only links via `Employee.user_id`). Skip the docstatus/submit layer — a status column suffices.
**Next**: Department tree + department approvers; Attendance (manual Present/Absent/On Leave, `check_leave_record` auto-fill); Leave Ledger Entry for audit + carry-forward expiry; `applicable_after` probation gate; Leave Block List.
**Later**: Employee Checkin + auto-attendance thresholds, Shift Request, compensatory/earned leave, Expense Claim, Payroll, onboarding/separation, appraisal.

## 5. UI patterns worth copying

- **Leave calendar with quick entry** (`leave_application_calendar.js`): drag-select on a month grid → dialog pre-fills from/to, filters `leave_type` to types with an allocation (`get_leave_details`), live allocated/used/remaining + `total_leave_days`, auto-resolves approver. `get_events` merges department members' leaves, block dates and holidays into one feed (`add_leaves`, `add_holidays`).
- **Shift calendar** (`shift_assignment_calendar.js` + `get_shift_events`): assignments expanded to per-day timed events titled `employee: shift` — a ready team-availability view.
- PWA (`frontend/src/components/`): `LeaveBalance.vue` + `SemicircleChart.vue` gauge, `AttendanceCalendar.vue`, `Holidays.vue`, `RequestPanel.vue`/`RequestActionSheet.vue` inline approve/reject.
- Reports (`hrms/hr/report/`): `employee_leave_balance`, `employee_leave_balance_summary`, `monthly_attendance_sheet`, `shift_attendance`.

# Digest policy, worker and API contract

## Policy and approval boundary

`DigestPolicyV1` is strict server-only configuration. Reject unknown keys, non-finite amounts, invalid identities, unsupported locale, source count above 5, missing dependency anchor/commit/lock hash, and missing/expired approval or unsupported output/cost bound. Ship `enabled:false`, zero approved spend and no production owner. The trusted activation path provides one canonical personal-org ID/owner profile; query/body values never select another owner. Business org, missing membership/owner, disabled Pulse module or missing current capability fails closed. An environment provider key is transport material, not authorization to spend.

Source IDs/endpoints are repository managed official feeds/APIs for present Minion package dependencies. Policy fixes exact origin/path/query and optional exact redirect destinations; only HTTPS, no URL username/password, fragment or arbitrary port. Source URL in an upstream item is evidence, never a newly fetched destination. Every item binds the frozen repository dependency/file anchor. Unknown package relation yields excluded reason; no model decides which private source to access.

Use a stable approved budget namespace independent of policy revision. Retired namespace rejects all further input. Policy reconciliation compares revision, approved limits and owner and invokes scoped cancellation/fencing on disable/change. Worker admission/publication rereads current membership, module enablement and role/grant rows with D's fresh-authority helper; cached capabilities alone are insufficient. External lookups occur before short SQL transaction and their current rows are checked inside. No database lock spans DNS, HTTP, provider or gateway calls.

## Fetch contract

`collectDigestSources(policy, checkpoints, {signal,deadline})` fetches at most 5 sources with concurrency 2 and aggregate budget 15000ms. Each source request has at most 10000ms including DNS/connect/TLS/headers/stream body and reads at most 1048576 bytes. At tick deadline abort every outstanding request and await bounded cleanup. Zero redirects by default; only explicitly enumerated allowlist redirects may be followed with each connection revalidated and within the original deadline/byte budget.

`pulse-digest.fetch.ts` uses Node HTTPS with a request-local `lookup` callback that resolves all addresses, rejects any non-public result and connects to a validated address. Reject localhost, unspecified, loopback, private, link-local, CGNAT, multicast, documentation/reserved and IPv4-mapped blocked IPv6. Preserve original hostname for TLS certificate/SNI; do not turn off certificate verification or substitute an IP URL. Check resolved socket destination agrees with the validated address before accepting bytes. No operator suffix/CGNAT bypass, ambient proxy, global-agent override or second uncontrolled lookup. Pin/revalidate each connection; a prior `assertSafeUrl` check alone is insufficient. Validate protocol/host/port/path before DNS. Test DNS answer change and mixed public/private answer sets.

Use If-None-Match/If-Modified-Since from accepted checkpoint only. A 304 requires retained accepted evidence; missing retained data cannot be interpreted as unchanged successful input. Fetch errors/partial collection fail the whole collection generation and advance no source cursor. Over-limit input is a typed failure, not silent lossy truncation. Normalization orders source IDs/items deterministically; snapshot identity excludes fetch times and transport-only ETag. Accept at most 20 items/49152 UTF-8 normalized bytes. Store immutable public source/content/hash/time plus dependency/file anchor; no credentials or private transcript data.

## Collection and tick

D's GET `/api/pulse/tick` remains exact CRON_SECRET bearer authenticated through `cron-auth-path.ts`; no anonymous prefix exemption or browser auth bypass. E extends `pulse-tick.ts`, importing dispatch and digest registration explicitly. Trusted configuration determines one org/owner and allowed job families. Reject org/type query selectors; preserve default `/api/jobs/tick` behavior.

Tick starts a monotonic 50000ms deadline. Read current configured owner/policy, atomically claim due collection row under its existing namespace key: current enabled policy, due next_poll_at, no unexpired lease; increment generation, random owner, expiry now+30s. Fetch outside transaction with <=15s aggregate deadline/concurrency2. In a short transaction recheck collection owner/generation/expiry, current policy/authority and admitted checkpoint revisions; deduplicate logical run and enqueue only once through D's transaction-taking API. Collection never calls the model or commits accepted source cursors. Release matching collection lease and set next_poll_at to now+15min on success or now+5min on failure; failed/revoked stale owners cannot advance it. A lost collection lease is safely reclaimed after expiry because only public reads occurred.

A successful collection creates at most one logical run and its background job atomically, including a deterministic unchanged-input run. The selected worker settles that run through a no-signal branch with zero model calls and the same current-authority/CAS transaction invariants. Duplicate input returns its existing run/job without another enqueue; terminal duplicates leave the queue empty. Partial source failure never admits a mixed snapshot. If another active run owns the namespace, record busy/deferred without another unbounded queue row.

Drain only D's selected `pulse_dispatch|pulse_digest` families for configured owner/org with the remaining tick deadline and due predicates. Source collection and dispatch cannot secretly leave thirty seconds of inference outside the handler budget. Expose remaining time to the handler; require >=30000ms plus a bounded 2000ms local settlement allowance before reasoning admission. Otherwise keep the queued job due for a later minute without consuming attempt allowance. D selected runner must not apply generic 25s cap to this 30s admission. Lease loss aborts cooperatively and blocks local writes; it never proves remote cancellation.

## Admission, reasoning and settlement

`queueDigestSnapshotTx` locks namespace, verifies owner/current policy and existing logical run unique key, inserts new run/job together; duplicate returns original even after terminal outcome. Do not use `createJobRequest` as dedup. Run immutable input includes source revisions, policy/model descriptor, request hash and bounded evidence. Before model admission the actual request is <=65536 UTF-8 bytes including schema/system instructions.

Under `JobExecution.withOwnership`, domain scope rechecks owner/policy/checkpoints and namespace fence/limits. `reasoning_admitted`, authoritative attempt UUID, admitted budget day/generation, attempted_calls increment, approved per-call reservation and active run slot commit atomically. Count at most 5 admitted calls/day and cap total known+reserved exposure by approved limit. All arithmetic is integer micro-USD with overflow/negative checks. Call count stays consumed even for a later proven unsubmitted attempt; releases of reserved exposure require authoritative attempt-matched proof. Policy revision/midnight cannot erase unresolved reservation/fence.

`pulse-digest.reasoning.ts` uses the existing `$server/llm` metered factory with narrow optional digest transport settings, leaving ordinary callers unchanged. Use exactly one request (`generateText` or the installed provider's equivalent), `maxOutputTokens:1024`, `maxRetries:0`, `AbortSignal` for total 30s, no tools, no step loop and no schema-repair call. Verify serialized wire output bound and provider routing option that disables fallback; absence of a supported bound/fallback control denies admission. No `models` fallback list. Requested/resolved model drift records receipt and fails qualification; no second model request. Use explicit configured model and approved price/exposure revision, never hardcoded cheap-model fallback.

Opt-in transport captures a bounded terminal provider envelope/usage before custom schema validation and SDK parse errors can discard it; stream-read response <=65536 bytes. Persist the terminal response, request/provider identity, elapsed time and authoritative cost if supplied as `reasoning_received` in an owned transaction before parsing the digest object. Existing usage middleware remains accounting instrumentation, not the durable receipt. Do not treat an estimated/default zero price as provider-reported cost. Valid receipt can include known zero. Unknown cost/outcome fences namespace and terminalizes indeterminate in this milestone, even if some text arrived; do not publish it as a qualified paid result or retry. If SDK parsing fails but bounded terminal envelope supplies trustworthy known bill, persist bill then fail validation with no recall.

Restart from received uses stored bytes/usage and performs only local validation/publication. Restart from admitted or lost response is indeterminate; no reset/retry API and no automatic fallback. Only queued, proven pre-admission failure can postpone 5s then 30s under D's atomic postpone result, maximum 3 then failed. Pending budget-slot/deadline deferral is not a provider attempt and cannot hot-loop in a tick. Settlement matches exact active run/attempt/generation/day; late output cannot release another run. Positive operator reconciliation needs actor/reason/evidence audit and never re-enables the same logical attempt.

## Result and publication

Strict result: `disposition:'actionable'|'no_signal'`, list of allowed source IDs and exact affected dependency/file anchors, supported claim, relevance/actionability explanation and suggested next step. Unknown keys, nonexistent citation/dependency, oversized card content or missing evidence fails with retained bill and no cursor advance. Text cannot become instructions/tools/URLs to fetch. Card limits match existing Pulse: title<=500, summary<=4000 characters, payload<=16384 bytes. At most one card per logical run; no-signal has bounded reason and no card.

`insertInternalPulseProposalTx` implements D's agreed signature and complete immutable binding check in new `pulse-publication.ts`. Reserved dedup key is `internal:dependency-digest:v1:<logical-run-identity>`. Public/gateway `validatePulseProposals` rejects that prefix and internal binding fields anywhere they could be interpreted as authority. User input cannot claim owner/run identity.

Publication order inside one `withOwnership` transaction: fresh authority/current policy; check all expected source revisions; read/insert internal card with org/owner/run/policy/input/result/content binding; CAS all source checkpoints; run terminal state/card; restore bookkeeping role; matching job terminal/cursor state. Throw rolls everything back. Existing matching complete binding returns same card ID without overwriting decided content. Mismatch is conflict, no cursor advance. Cursor conflict commits superseded terminal job/run only, no card/cursor change. No-signal commits reason/checkpoints/run/job together. Invalid or unknown output commits failure/indeterminate only. Model citation existence is structural evidence, not entailment proof: human/sample claim-support review and stop-on-confirmed-unsupported-claim is a separate pilot promotion gate.

## Feedback and export

POST `/api/pulse/proposals/[id]/feedback`: Supabase session, current personal owner, Pulse edit capability and same-origin mutation guard; strict `{clientActionId,expectedContentRevision,reason,comment?,supersedesFeedbackId?}`. GET same route requires Pulse view plus owner. Validate digest/card/run binding server-side. Reason enum and comment<=500 characters from data model. Same client ID+same input returns same row; same ID different content conflicts. Corrections lock current predecessor, append one successor under unique predecessor constraint and preserve old record; reject self/cross-owner/cross-card/stale-content/corrected-predecessor.

GET `/api/pulse/feedback/export`: current owner plus `pulse:export`, keyset pagination <=100 rows, bounded JSONL response <=256 KiB; identifiers/revisions and approved bounded comment only. Separate `factual_errors` (`fact_error`) from `preference_relevance` (other reasons), with explicit schema/version and no raw source prompts. Selection/approve/dismiss is not inferred feedback. Export is a read; no send/upload or learning side effect.

UI uses shared Button/Select/FormField/status/async primitives on existing Pulse card/receipt; all copy uses `m.*()` EN/ES. Failed save retains selection/comment, committed-refresh failure triggers read reconciliation only, repeated network writes retain same action ID only for explicitly idempotent retry. Keyboard controls and status aria-live work; no second global spinner or new dashboard. New API routes use existing Pulse prefix plus handler-level view/edit/export/owner checks; route/capture manifests and existing nav gate are verified.

## Retention and cancellation

Extend D cancellation transaction for queued digest runs/jobs and collection generation, triggered by policy reconciliation and existing membership deletion/update. Independently recheck authority before every admission/publication. Raw evidence/responses/comments redact after 30 days by default in bounded tick housekeeping, at most 100 rows/tick and within the 50s budget; queued required-data expiry cancels. Preserve minimal admission/binding/cost/tombstones. Namespace retirement precedes tombstone deletion, so replay cannot create a new paid request. No cascade deletion from owner/profile or source removes admission history. Rollback disables admission, cancels queued scoped work and retains readers/fences; older binaries must not resume automatic retries.

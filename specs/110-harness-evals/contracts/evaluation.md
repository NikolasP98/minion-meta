# Evaluation data, CLI and approval contract v1

## Manifest and approval

`EvaluationManifestV1` is strict JSON. Canonical serialization sorts object keys, preserves array order and rejects nonfinite numbers/duplicate JSON keys. Freeze its SHA-256 before any run. It contains:

| Field group | Required values |
|---|---|
| Identity | version, experiment ID, run purpose (`software_fixture|router|screen|complaint`), mode, creation time, seed, operator reference |
| Provenance | exact source commits and lock hashes for meta/Hub/optional C; adapter/build hash; requested and permitted resolved model IDs; provider profile/version; tool/catalog/data/fixture revision; schema/question/gate/threshold/scoring-rubric revisions |
| Corpus | frozen split manifest hash, selected episode IDs or a sealed held-out index, development/holdout purpose, episode cluster/leakage groups, expansion/stopping rule and authorized unblinding reference |
| Scope | actor/org disposable fixture IDs, allowed side effects only inside marked fixture state, denied production endpoints, approved credential input reference (never a value) |
| Bounds | maximum calls/attempts, input/request bytes, output tokens, per-call/run/UTC-day USD limits, conservative input/pricing/exposure rule revision, total duration/effort, cancellation/stop conditions |
| Evidence | expected receipt kinds, raw artifact retention deadline, replay-namespace lifetime, restricted artifact destination |
| Experiment gates | router frozen tolerance/seed/draws; screen fixed review budget/control sample and severity miss bounds; complaint frozen threshold/development evidence/severity bounds, only when that experiment is enabled |
| Approval | separate approval reference; absent is permitted for `software_fixture` only. The attestation digest is stored in the run receipt, outside the hashed manifest, avoiding a circular hash dependency |

A generated manifest is an intent artifact, not approval. Live requires `--live`, `--manifest`, `--approval` and an explicitly configured trusted public key/owner reference outside the manifest and run-output tree. Use built-in `node:crypto` to verify a small detached Ed25519 attestation over canonical `{version, manifestSha256, approvalRef, ownerRef, issuedAt, expiresAt, permittedMode:'live', scopeHash, budgetHash, approvalNamespace}`. Match all values to the manifest and explicit trusted configuration; reject expired/not-yet-valid, replaced key, wrong hash, unsupported algorithm, invalid signature and self-declared manifest key. No signing/minting CLI, discovery of user keys, approval API, automatic trusted-file creation or “approved:true” shortcut exists. Test-only fixtures use a test-only keypair and cannot match an operational trust root.

This signature proves consistency with an operator-configured authority; it does not invent authority from a name. The human responsible for a later paid operation must supply the approved attestation/trust configuration explicitly. Developer tests inject a stub transport using the same live provider code; operational CLI has no secret-discovery fallback. Trusted key/approval files are read-only inputs. Reject symlinks/path traversal in generated artifact roots and never put credential values in the manifest, arguments receipt or stdout.

Provider profiles initially mirror existing integrations: OpenRouter decisions at `https://openrouter.ai/api/alpha/decisions` for Jev and OpenRouter chat completions at `https://openrouter.ai/api/v1/chat/completions` for main inference. These are fixed code allowlist entries, not arbitrary manifest URLs. The manifest selects a supported profile/model. Exact request/result schema and versioned exposure policy are qualified with stub wire fixtures; unsupported provider contracts fail closed. No model-price values are claimed current by this SDD; operator-supplied versioned approved values are required for live admission.

## Episode, split and label model

`EpisodeV1` fields: immutable `episodeId`, `clusterId`, `leakageGroupId`, `family`, `locale: en|es`, source-truth references/hash, initial disposable tenant/role/data state and hash, all user turns/transitions, allowed and forbidden tools/actions, expected receipts/artifacts, independent terminal criteria, maximum effort/calls/duration, consequential-action flag and compaction/history fixture descriptor where applicable. Missing truth, permission matrix or receipt expectations is invalid. “No action expected” is an explicit empty requirement plus forbidden side effects, not a missing field.

Families are exactly the parent's twelve: informational question, lookup, authorized form fill, multi-intent navigation, off-page discovery, UI choice, artifact callback, short continuation, changed page, compacted/history-limited session, tool/provider failure, cancel/scope transition. Small software fixtures represent both languages, consequential actions and compaction; they are labeled `synthetic_software`, never counted as human-adjudicated holdout evidence.

`LabelV1` records episode/source revision, label ID/revision, actor/reviewer reference, method `human_adjudicated|synthetic_software|unadjudicated`, independent rubric revision, terminal outcome and authority/severity findings, adjudication reference/time and superseded label when corrected. Import never silently upgrades method. Screening output is a separate file and cannot write labels. Human review occurs without seeing screen output. Invalid/unknown truth remains unadjudicated/abstain, not negative.

`SplitManifestV1` lists episode ID, cluster/leakage group and canonical truth/turn hash per split. Duplicate IDs or equivalent fixture variants sharing a leakage group across development/holdout reject. Content hashes detect exact normalized duplicates; translation/rephrasing groups must be assigned during human curation. The validator does not claim semantic near-duplicate detection from hashes alone. Corrections create a new split revision; holdout already inspected cannot silently be reused for tuning then validation.

Development commands read only development bodies/labels; the sealed holdout index exposes counts/opaque IDs/hashes, not bodies/labels. Runner refuses a holdout file path/split in dev mode and does not load that file before rejection. Explicit holdout mode requires the frozen manifest and authorized unblinding record. Readiness target: ≥60 development and ≥240 held-out episodes, twelve families, both languages in each applicable family and ≥40 consequential-action episodes, counted only for human-adjudicated matching revisions. Report missing counts and coverage per stratum. Collecting/adjudicating that corpus is a separate governed operation, not unfinished runner software.

## Run, attempt and receipt lifecycle

Create a fresh private `runs/<run-id>/` (0700 directories/0600 files) containing frozen manifest/approval digests, `events.jsonl`, `receipts.jsonl`, admission ledger references and `result.json`. Do not overwrite an existing run. Each JSONL record has schema version, UUID identity, run/episode/cluster/arm/attempt/root/submission relations, timestamps, source/model/rubric revisions, kind and bounded typed payload. Write/fsync admission before calling transport. Raw fixture inputs are private run artifacts under manifest retention, not analytics.

Run states: `prepared → running → complete|incomplete|canceled|indeterminate`; invalid manifest/admission never enters running inference. Attempt states: `reserved → dispatched → received → settled`; `reserved → not_dispatched` only with positive proof the dispatch function was never entered; any crash/lost response/abort after durable reservation without that proof becomes `indeterminate`. Persist bounded response and supplied usage before downstream interpretation, so a malformed result can record known cost and fail without recall. Received results may resume local materialization/reporting only. Unknown dispatch never automatically repeats, including under a new run ID/approval alias.

One explicit budget namespace binds approval/operator/provider scope across runs and UTC days. Maintain a private append-only budget journal outside individual run directories with an exclusive single-writer lock. Namespace key is approvalNamespace plus immutable approved authority/scope binding, not run ID or mutable manifest title. Reservation charges conservative **upper** exposure in integer micro-USD (round upward); known bill retains exact reported USD for analysis. Enforce per-call/run/day limits and one active paid request in this small runner before dispatch; never infer an input bound from mean historical tokens. Request/output caps and approved conservative input-bound rule must establish an upper exposure from the exact serialized request. Unsupported/unknown pricing or bound policy rejects. Digest-profile output, if exercised, is ≤1,024 tokens or verified equivalent; other task bounds are explicit manifest values.

Settlement matches reservation/attempt identity once. Known charge releases unused reservation; actual overshoot is recorded and stops admission. Missing cost or incomplete retry coverage retains unresolved reservation and an unknown fence; a final resolved model alone does not prove complete billing. Midnight and new run IDs carry outstanding reservations; unknown fence remains. Concurrent process cannot acquire the namespace lock. On crash, recovery reads the journal conservatively; admitted work without a terminal receipt becomes indeterminate and no dispatch resumes. A leftover lock or truncated/corrupt journal fails closed. This small tool has no automatic stale-lock deletion or spend-unfencing CLI: an operator first confirms the process stopped and records audited reconciliation; absence of a provider receipt never proves zero billing. Test crash/reopen refusal with subprocesses, not only mocked write functions.

Cancel/timeout stops future admission, aborts adapter/provider cooperatively, persists cancellation plus unknown exposure if dispatched, drains received evidence within the manifest deadline and closes only owned processes. No automatic SDK retry/fallback/redirect. A separate explicit retry, when authorized and proven safe, is another admitted attempt and cost; an ambiguous request never qualifies as safe. Tests use stubs and an external-network denial guard even when `--live` is exercised.

Retention uses explicit manifest expiry; `corpus` source/labels follow their separately approved retention. Add `run.mjs inspect` and `run.mjs redact --run` local operations: redact raw fixture input/response/tool payload after expiry or authorized deletion, retain minimal hashes/IDs/admission/unknown tombstones and aggregate receipts while the namespace can be replayed. Redaction requires no active writer and cannot recreate inference. Use `run.mjs retire-namespace --budget-journal ABS --namespace ID` only with no active writer; append and fsync an irreversible retirement marker to the persistent namespace registry before any eligible tombstone deletion. Never remove that minimal retirement marker. Retirement prevents future admission and cannot erase unresolved spend obligations; unknown accounting remains retained. A retired namespace is permanently refused, including under a new run or approval alias with the same binding. Do not commit private raw trace payloads or real approvals/credentials; only small synthetic fixtures belong in git.

## Deterministic outcome and economics

`TaskOutcome` is `success|incorrect|blocked|canceled|indeterminate`, with independent rubric/label revision and required receipt completeness. Client `transport_submitted` is not gateway acceptance; a matching accepted receipt is not successful domain action. Deduplicate exact event/receipt IDs; conflicting duplicates quarantine, never last-write-wins. Missing required receipts lower coverage and prevent success/promotion. Join only explicit root/parent relations; evaluator episode metadata joins multi-turn natural-language continuations without adding production task state.

Cohort key includes source, dependency lock, requested/resolved models, provider profile, tool/catalog/data fixture, schema/question/gate/threshold and rubric revisions. Drift yields separate cohorts; mismatched arms cannot be pooled into a matched promotion comparison. Report per-attempt and per-started-task cost, total wall time, all attempts/retries/discovery calls, token/cache use where supplied, known-bill coverage and unresolved exposure. Never drop failures from the numerator.

For each arm, `CPS = sum(all cohort costs)/count(successful episodes)`. Bootstrap matched episode clusters 10,000 times using frozen seed and percentile 95% intervals; preserve repeated observations within a cluster and recompute the full statistic for each draw. Do not average per-success costs. Apply the same paired cluster draws to success difference and p95 latency ratio. Pre-register how repeated runs contribute episode success and wall time; default one observation per arm/episode, repeated studies must declare their aggregation before unblinding. A bootstrap draw with zero baseline/candidate successes is undefined/nonfinite and cannot be silently dropped to narrow intervals; report its mass and fail the cost-promotion gate if the required upper bound is not finite. Use conservative adverse bounds for bounded unknown cost (candidate high/baseline low) and report this fact. Unbounded exposure, zero success, incomplete pairs/receipts, drift or missing preregistration is nonpromotable/inconclusive.

Promotion recommendation requires parent gates together: zero additional unauthorized/wrong-scope/duplicate/post-cancel actions; paired 95% success-difference lower bound ≥−0.02; paired 95% cost-per-success ratio upper bound <1; paired p95 latency-ratio upper bound ≤1.10 (conservative interpretation of the parent's paired latency procedure). Record stopping/expansion and power limitations. Full-corpus readiness and independent labels are required for a quality recommendation; tiny synthetic runs can prove calculation logic only. Output is `baseline_retained|candidate_eligible_for_human_review|inconclusive`; it never changes policy/release state.

## Screening

Run receipt checks first: unauthorized tool, missing action receipt, hidden tool failure, duplicate action, post-cancel send and unsupported cited ID. Each check returns typed `pass|fail|abstain|not_applicable` with evidence pointers/severity. A critical failure veto is not averaged away. Semantic screening addresses only claims receipts cannot settle, with a separately versioned rubric and independent typed abstention. Fixture mode uses frozen semantic outputs; any later live semantic call goes through the same approved adapter/accounting, never a hidden provider request.

The screen command never loads gold labels during scoring; evaluation joins an independently supplied frozen label file afterward. Selection is fixed-budget `random` versus `prioritized_plus_controls`, each deterministic under the frozen seed. The manifest preregisters budget, apparently-good control count, strata and severity miss bounds. Preserve selection probability for each reviewed trace; compute weighted missed failures (e.g. Horvitz–Thompson contribution `failure/probability`) within the declared stratum, with uncertainty from the preregistered stratified bootstrap. Unreviewed, unlabeled and abstaining traces are not known good. Missing controls/labels/probabilities or unsupported uncertainty procedure returns inconclusive, not zero misses. No customer output, billing adjudication, learned weights or release authority.

Optional E feedback import validates its versioned owner/content/source/policy revision export and keeps factual-error reasons separate from preference/relevance. Only an explicit flag/path enables it; no Hub API call or E dependency in ordinary fixture tests.

## C/F complaint record

C owns the real watcher eligibility/census/shadow implementation and the authoritative [`ComplaintEvaluationRecordV1` contract](../../107-harness-gateway/contracts/usage-shadow.md#exact-cf-export-schema-v1). Its implementation schema is `extensions/alert-watcher/src/complaint-evaluation.schema.json`; exporter is `complaint-evaluation.ts` in that directory. F reads that schema and C-emitted frozen fixtures from an explicitly pinned Gateway checkout/artifact, recording Gateway commit and schema SHA-256 in the manifest. Missing or mismatched schema identity rejects before analysis. Do not maintain a second schema, invent field aliases or clone eligibility logic in meta.

Use exact C names: `schemaRevision:'complaint-evaluation-v1'`, stable `recordId`, positive safe-integer `receiptRevision`, `logicalSourceId`, `authorityNamespaceHash`, admission/result IDs, immutable input/policy/model binding, `eligibility.status/reason`, baseline disposition, gate disposition `forward|negative|abstain|unavailable`, purpose-tagged attempts, and complete/incomplete cost/deadline coverage. Validate every required nullable field, strict bounds and reference/purpose constraints against C's schema. C's deterministic eligibility output is evidence from the producer; F reports eligible/bypass/disabled strata and typed reasons without reclassifying a custom/idless/drifted source as eligible.

Identical same-revision re-exports deduplicate; conflicting same-revision facts quarantine. Higher revisions may only extend admitted to permitted terminal receipt states with unchanged immutable binding, never replace a known bill or conflicting terminal fact. Lower revisions cannot overwrite later evidence. Attempt IDs deduplicate actual cost across records/revisions; `logicalSourceId` deduplicates the event denominator. The denominator is eligible logical sources, never hook invocations or only forwarded positives. Distinct policy/source/generation identities remain distinct.

A shadow record requires the baseline even when the gate is negative; missing baseline is incomplete. Sum all actual gate, baseline and suggestion attempts, known failed calls and bounded unknown exposure. `forwardedBaselineAttemptIds` is only a counterfactual selected subset: report its hypothetical active cost separately with assumptions, never omit actual shadow baseline bills to claim realized savings. Denied/unsubmitted gates with empty attempt references add no fabricated bill. An admitted unknown stays unknown, and timeout/abstain/unavailable/model drift never becomes a negative.

Independent severity labels join by record/input/policy revision and matching `severityLabelRevision`. The watcher's existing `low|med|high` severity is not an independent urgent/critical ground-truth label; the frozen adjudication rubric must define that mapping and missing labels are inconclusive. No eligible traffic produces `do_not_pilot:no_eligible_traffic`. Missing frozen development-selected threshold, sample-size/confidence-supported severity miss bounds or any additional urgent/critical miss forbids promotion. F has no active-gate control path.

## Commands and evidence limits

`run.mjs` is fixture by default. `--mode fixture --manifest FILE --hub-root ABS --out ABS` runs software fixtures. Live additionally requires `--live --approval FILE --trusted-key FILE --owner-ref REF --budget-journal ABS` and explicit provider credential input; no examples include operational secrets. `corpus.mjs validate|import|readiness`, `report.mjs --run DIR`, `screen.mjs --run DIR --labels FILE`, and `complaint.mjs --input FILE --manifest FILE --gateway-root ABS` are deterministic offline commands. Commands refuse paths/splits outside the approved inputs.

Fixture unit tests, real Hub adapter integration, full held-out evaluation, approved live smoke, active promotion and production release are separate statuses. The first later approved live smoke is at most one case per arm; receipts/cost coverage must be checked before any continuation. This batch executes zero paid requests.

# minion-base v2 — SDLC Kanban, Practices Codex, Agentic-Dev Research

**Date:** 2026-08-12 · **Repo:** `NikolasP98/minion-base` (private, `main` → Vercel → base.minion-ai.org) · **Status:** implementing

## 0. Product

v1 shipped a single-page pipeline overview. v2 turns base into the *development lifecycle system of record* the user asked for:

> "development run fully/partially autonomously by agents … encapsulate the dev patterns into something visual … I want to see everything in a kanban format … view toggle for every repo … deep research on how tech enterprises are running their fully automated agentic development systems."

Three deliverables, one roadmap section:

1. **/kanban** — the SDLC as a live board. Columns = the stages we actually practice (Proposal → Spec → Development → Testing → Deployment). Cards derive from live GitHub state; per-repo toggle chips filter the board (MINION core repos on by default).
2. **/practices** — the codified SDLC: every rule and practice we've established *and corrected* over time (mined from memory files, AGENTS.md, specs/, git history), plus the dev patterns (spec-first, multi-agent co-development, worktree isolation, memory loop) and a process-evolution timeline.
3. **/research** — enterprise agentic-development research: real systems (Devin, Copilot coding agent, Jules, Codex cloud, Claude Code fleets, …), themes (shared memory, human gates, next-step planning), and recommendations mapped onto MINION's self-hosted Netcup + worktree-per-feature setup.
4. **Autonomy roadmap** (inside /research) — the target: Claude Code/Codex runners hosted on Netcup, one isolated worktree per feature, PR-native approval gates (already spec'd in `2026-08-07-projects-github-repos-and-factory-gates-spec.md`; preview-runner extension exists on gateway `6b04afff7`).

## 1. Architecture

Unchanged from v1: SvelteKit 2 + Svelte 5 runes, Bun, adapter-vercel (`nodejs22.x`), no DB, fail-closed basic auth in hooks. GitHub fan-out stays in server `load` with `s-maxage=300`.

New: static curated data modules generated by mining/research agents, committed as source:

- `src/lib/data/practices.json` — `{ stages, rules, patterns, timeline }`
- `src/lib/data/research.json` — `{ systems, themes, recommendations }`

These are editorial content, not live data — a JSON file beats a CMS here. Refresh path: re-run the mining agent, review diff, commit.

### Kanban derivation (live)

| Column | Source |
|---|---|
| Proposal | open issues (non-PR) per repo |
| Spec | `specs/*.md` from minion-meta contents API (matched to repos by filename keywords) |
| Development | open PRs + draft PRs; recent branch commits |
| Testing | latest workflow runs (in_progress/queued = testing; failures surface red) |
| Deployment | most recent success run + latest commit on deploy branch |

Repo filter = client-side `$state` set of repo ids, chip toggles in the board header; default = core repos (gateway, hub, site, meta). No URL state, no persistence — YAGNI.

## 2. Design governance (minion-base's own, not hub's)

- `src/lib/design/tokens.css` — the only place raw color/size values may appear. Semantic tokens (`--bg`, `--surface`, `--surface-2`, `--border`, `--text`, `--text-dim`, `--accent`, `--ok`, `--warn`, `--err`, spacing/radius/type scale).
- `DESIGN.md` — one-page law: token usage, component idioms, density rules.
- `scripts/lint-design.mjs` — fails if raw hex colors appear in `.svelte` files outside tokens.css. Wired as `bun run lint:design`; run before every deploy. Debt starts at 0 and stays there.

## 3. Non-goals (this pass)

- Building the Netcup agent-runner infrastructure itself (visualized + spec'd only; factory-gates spec covers the mechanism).
- Persisted board state / drag-drop (the board mirrors reality; you change reality in GitHub).
- Auth beyond the existing basic-auth gate.

## 4. Gates

`bun run lint:design` → `bunx svelte-check` → `bun run build` → push → verify live (401 unauth / 200 auth, all routes render).

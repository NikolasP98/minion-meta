# Qualification runbook

This is planned implementation verification. No command below has been claimed as passed by the specification run.

1. Obtain owner approval of spec/plan. Use an isolated implementation checkout based on the registry's current Hub PR base. Reconcile source-evidence.json and coverage.md before editing. Read minion_hub/CLAUDE.md and the UI governance skill.
2. Keep all DB/auth/browser work on the local seeded QA stack. Read `docs/qa-stack.md`; use the implementation base's `bun run dev:local` or `bun run qa:up`, and loopback-only `.env.qa.local`. Never copy production credentials to build/test processes.
3. Add focused failing tests, then implement slice by slice. Test the proposed `src/lib/branding.test.ts` with contracts/name-fixtures.json, service/endpoint tests, existing organization-provision tests and layout tests with `bun run vitest run <explicit paths>`.
4. Register new SQL cases in scripts/qc/native-postgres-manifest.ts, then apply migration through the existing QA migration runner. Run seed verification and native authenticated SQL tests: own-member SELECT, staff/owner direct UPDATE denied, foreign-org SELECT denied, permitted platform-admin role behavior unchanged; service writer only admits owner of active org. Check constraint and idempotent migration/seed paths. Inspect exact final policies, not just baseline SQL.
5. Compile strings with `bun run i18n:compile`. Run `bun run check`, `bun run test`, and `bun run build` using disposable QA env. Confirm the build's migration hook cannot address production. Run `bun run lint:design` and `bun run lint:tokens`. Run applicable access/route/accessibility checks from that base's package.json and CI; record exact commands/outcomes.
6. Use browser-harness against the local fixture. Verify actual SSR text with JavaScript disabled and hydrated text with JS enabled. Test owner/staff/second-org sessions, failed saves and Retry, org switches and delayed results, logout/back, refresh as another member, and retrying partial creation.
7. Capture actual wordmarks/Appearance/create form in EN/ES, light/dark at 320/390/401/430/768/1280px and 200% zoom. Test MINION, Faces, wide letters, CJK, accents and maximum allowed emoji. Measure clipping/overlap and text extents. Existing ≤400px icon-only mode must still expose the full accessible name; 401px text must actually be visible.
8. Close every Hub identity inventory row with binding and proof, and classify every newly found candidate/exclusion. Perform independent Standards and Spec reviews. Every unchecked implementation gate remains open; use the required TODO(handoff)+proposal ledger for discovered implementation defects.
9. Deliver reviewed PR slices and exact evidence. Human merge, branch-triggered deployment, and authenticated post-merge verification are separate gates. Revert application first if needed, retaining the additive column and saved names.

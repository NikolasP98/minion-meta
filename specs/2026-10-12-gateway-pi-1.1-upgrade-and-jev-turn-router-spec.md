# Spec — pi 1.1.0 upgrade and JEV turn router

## 0. Product

The owner wants the gateway's agent runtime on current pi (codemode, MCP, System-1
classifiers) and the hub assistant to stop spending ~4,300 tokens per turn on context the
turn does not need. In the owner's words: "its main goal is to optimize that 4k token per
turn. as well as codemode with smart mcp use."

**Out of scope:** the gateway `before_tool_call` JEV guard (S3) and classify-in-sandbox
(S4) from the proposal; the CRM insights chat envelope; any MCP server catalogue beyond
config plumbing.

Owner gate 1 (approval): 2026-10-12 — "yes, proceed. Also, for the JEV implementation,
its main goal is to optimize that 4k token per turn. as well as codemode with smart mcp
use." The two-pass spec review is collapsed into the implement → independent audit → fix
loop per slice (noted here as the bypass the SDLC contract requires).

## AS-IS

- Gateway `minion/` DEV: `@earendil-works/pi-{agent-core,ai,coding-agent,tui}` pinned
  `0.75.5`. Bumping to `1.1.0` yields 95 type errors in 30 files (42 in tests); dead
  exports and shape changes are enumerated in the proposal. No codemode, no MCP client.
- Hub `minion_hub/` master: `buildAssistantContext()` prepends a 14,202-char briefing
  (110 pages ≈ 9.6K, 4 UI tools ≈ 4.6K, 8 forms) + ~3K prose to EVERY assistant turn,
  ≈ 4,300 tokens, regardless of what the user asked. Call sites:
  `FloatingAssistant.svelte:206,954,958` and `CrmInsightsChat.svelte:92`
  (`buildInsightsContext`, out of scope). No turn-level classification exists.

### Slice 2 — hub JEV turn router, goal: cut the ~4.3K tokens per turn (S2)

**Topics:** `logic`, `security`

- Server: `POST /api/assistant/route` `{ text, locale }` → `{ mode, manifests, ms }`,
  `requireAuth`. One Typesafe Jev request through the hub's existing OpenRouter key
  (`OPENROUTER_API_KEY`, decisions endpoint, model `~typesafe/jev-latest`): one `choice`
  (`navigate | record_action | data_question | knowledge_question | chat`) and one `noul`
  per manifest. Timeout 1,500 ms. Any failure → `{ decision: null }` with HTTP 200
  (fail-open). Server captures PostHog `assistant_route` (mode, probabilities, ms, cost,
  gated=shadow|enforce) via `captureServerEvent` (add the event to the allowlist).
- Client: `buildAssistantContext(decision)` keeps the route/focus/org lines and the UI
  tools core unconditionally; gates **pages** (p(navigate) ≥ 0.5), **forms**
  (p(record_action) ≥ 0.6), **data-tools prose** (p(data_question) ≥ 0.5), **brain
  prose** (p(knowledge_question) ≥ 0.5). Mode comes from `PUBLIC_ASSISTANT_ROUTER`
  (`off | shadow | enforce`, default **enforce** — the owner's stated goal is the token
  cut; `shadow` logs the decision and still sends everything; `off` skips the call).
- Invariant: a navigate-intent turn still receives the full page list; a null decision
  always yields today's full envelope; the user's text is never altered; the route call
  never blocks a send for more than 1.5 s.
- Invariant: the route-contract ledgers (6 counts) are updated for the new endpoint.

### Slice 3 — codemode + MCP in the gateway, after Slice 1 (S1)

**Topics:** `infra`, `logic`

- Gateway sessions bound to the hub channel declare `codemode` (pi `defaultTools` /
  `codemode.mode`) behind `MINION_CODEMODE=1`; existing 67 tools keep `direct` exposure
  until measured. MCP servers come from gateway config (`mcp.json` equivalent in
  `MinionConfig`), default `codemode` exposure so they never enter the declared tool
  list. Measure prompt tokens on the 20 use-case prompts before/after.

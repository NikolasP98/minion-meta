# Formula properties

## AS-IS

At Hub master 55f525c, custom-properties.ts admits six input types. Definition rules are organization-scoped JSONB; values use explicit null versus absent/default projection, versions and forced RLS. custom-property-bundle.service.ts authorizes records before loading values. POS catalog +page.server.ts derives native margin from listSellables unitPrice and costForProducts canonical recipe cost. Margin is money, not the payload-only margin percentage. Finance-sensitive viewers receive null cost/margin. DataTable supports shared custom cells and client query/export, with custom server operations disabled for CRM.

## TO-BE

1. Formula is a seventh custom-property type on all eight registered tables. Scalar custom text/number/date/boolean properties and other formulas can be referenced; unsupported select collections/relations fail explicitly. Native source admission begins with POS catalog sale price, estimated unit cost and native margin. Inputs come from server adapters, never browser rows or rendered text.
2. SQL-style authored syntax uses double-quoted property labels, single-quoted string literals, numeric/boolean/null literals, + - * /, comparisons, AND/OR/NOT, IS NULL, parentheses, CASE WHEN THEN ELSE END, and allowlisted scalar functions ROUND, ABS, COALESCE, NULLIF, LEAST, GREATEST. No SELECT/FROM/JOIN, arbitrary functions/casts, SQL comments/statements, relations/aggregates, dynamic SQL or eval. Labels may be localized; persisted AST references stable source IDs/property UUIDs. Rename never rebinds a dependency. Ambiguous/unknown labels diagnose, not guess.
3. Shared parser and type checker provide ranged diagnostics for syntax, unknown/restricted/archived references, incompatible operands/function arguments, invalid output and cycles. Number-plus-text and date arithmetic fail before save. Numeric types preserve money currency/unit basis: money +/- matching money; money * or / unitless number; matching money / money gives ratio. Cross-currency or incompatible dimensions reject. Plain custom numbers remain unitless. Null propagates; COALESCE is explicit. CASE conditions are boolean and branches must have compatible types. Bounded expressions: 2,000 characters, 256 nodes, depth 32, 64 direct dependencies; definition graph remains within the existing 100-active-property cap.
4. Server independently parses/checks on save/preview. Persist language version, canonical AST, inferred output, dependencies and audit/version metadata in definition rules; never trust client-supplied compiled metadata. Formula definitions have no default and no stored cells; value PUT rejects them. Converting a populated input to formula is rejected. Formula evaluation occurs server-side after entity authorization and scalar/default projection. Bounded parameterized PostgreSQL numeric expression evaluation supplies one authoritative result; authored SQL is never executed. No per-cell database or external-provider calls. SQL fragments come only from checked AST/allowlisted operators, with values bound as parameters.
5. Result cells distinguish valid, intentional blank, restricted, partial and runtime error states. Division by zero produces null plus a diagnostic without breaking other rows; NULLIF requests a blank. Restricted dependencies propagate even through COALESCE/CASE so null substitution cannot leak restricted inputs. Partial recipe costs propagate a visible warning. Decimal ROUND uses documented PostgreSQL half-away-from-zero semantics. The native JS rounding remains unchanged; the comparison must reveal rather than conceal any boundary differences.
6. Definition operations serialize the table dependency graph: reject direct/indirect cycles, archive of active dependencies, and type changes that invalidate dependents. Revalidate transitively; stale CAS still rejects. Renames preserve AST identities and display current labels when reopened. Archived formulas retain definitions and restore through graph validation. No change to native data/domain calculations.
7. Formula editor uses governed CodeMirror patterns with typed property/function completion, signatures, inferred output, keyboard completion and underlined diagnostics as the user types. Invalid drafts cannot save. Preview explicitly requests at most 20 authorized row IDs and returns source/result/quality and native comparison where applicable; no per-keystroke network requests. Errors are localized EN/ES. Formula cells render read-only values and actionable diagnostics. Numeric/money formatting remains numeric for sort/filter/export; money carries resolved currency. Formula source permission gates apply to catalog, definition metadata, preview and values; a formula owner never lends privileges to viewers.
8. First template is `ROUND("Sale price" - "Estimated unit cost", 2)`, label Margin (formula), on pos.catalog beside existing Margin. Template identity is durable and independent of label; idempotent opt-in installation targets only the user's identified organization and never overwrites edits/recreates archived definitions. No per-row values are materialized. Display both native and formula output, with bounded preview comparison reporting match/difference/unavailable and numeric delta. All remaining query/export limits inherit existing CRM restrictions.

## Frozen implementation contracts (pass 2)

The following details resolve the two review passes and take precedence over abbreviated wording above.

- The SQL compiler evaluates typed scalar number/text/date/boolean expressions. Numeric operands use PostgreSQL numeric, never float; JSON outputs are finite JS numbers, strings (date-only YYYY-MM-DD for date), booleans or null. Money has numeric value plus resolved ISO currency and per-sellable-unit basis. Limit evaluated numbers to the documented safe magnitude, report numeric overflow/nonfinite as runtime error. The engine must not let a pathological expression abort the whole table.
- Unary +/- are supported for numeric operands. Same-compatible-type comparisons are allowed, with money requiring matching currency/basis; equality to NULL follows SQL unknown, and IS [NOT] NULL is the explicit predicate. AND/OR/NOT follow SQL three-valued logic; CASE selects only a true condition and evaluates only its selected result. ROUND requires a bounded integer precision argument. LEAST/GREATEST ignore nulls unless all operands are null, matching PostgreSQL. COALESCE takes the first non-null compatible value; NULLIF uses compatible equality. Identifier/text escaping uses doubled double/single quotes respectively.
- Compiler returns guarded value and error fragments from the checked AST. Runtime errors respect CASE/COALESCE execution, so dead-branch division is not an error. Arithmetic overflow is bounded/guarded. Sensitivity and partial quality are static over all transitive dependencies, including dead branches, to prevent permission and completeness laundering. Quality precedence is restricted, error, partial, blank, valid; successful null is simply blank (no inferred claim of user intent). Partial/null inputs retain partial quality.
- Active quoted labels match exactly and case-sensitively against the current localized catalog labels plus documented EN/ES aliases for native fields. No stable key is guessed from arbitrary text. A native/custom or alias collision produces an ambiguous-reference diagnostic. Stable IDs exist internally only. Existing compiled AST is revalidated by ID on unrelated edits and rendered to current labels for the editor; never reparse stale authored labels after a dependency rename.
- Shared browser-safe parse/typecheck functions operate locally. Draft formula rules are `{type:'formula',expression:string}`; persisted/returned formula rules additionally carry server-owned compiled metadata `{languageVersion:1,ast,outputType,dependencies}`. The server discards any submitted compiled metadata and recomputes it. Existing unchanged formula rules may retain their stored AST on a metadata-only patch, but expression edits compile afresh. Formula/input conversion in either direction is rejected in this first slice; existing input-to-input behavior remains unchanged.
- Existing cell fields remain. Formula cells add `computed:true`, `definitionVersion`, and `formula:{quality:'valid'|'blank'|'partial'|'restricted'|'error',code:string|null,currency:string|null,sourceUpdatedAt:string|null}`. `present:false`, `version:0`, `value` and `effectiveValue` carry the computed scalar or null. Error codes are stable and localized by UI; source timestamps are null where canonical costing has no reliable timestamp. Diagnostic ranges apply to authored expressions, not interpolated sensitive values.
- Catalog endpoint: GET `/api/tables/properties/formula/catalog?tableId=...` returns `{fields:[{id,label,aliases,type,nullable,source}],functions,canManage}` after owning-module and sensitivity checks. Native money fields resolve organization currency via the existing canonical finance settings service; its explicit domain default is authoritative when no settings row exists. Invalid/unresolvable currency makes those native inputs unavailable with a diagnostic, never an invented PEN fallback in the formula engine.
- Preview endpoint: POST `/api/tables/properties/formula/preview` accepts `{tableId,expression,recordIds,propertyId?}` with at most 20 unique IDs. Returns `{diagnostics,outputType,dependencies,rows:[{recordId,inputs,result,nativeComparison?}]}`; result uses the formula-cell envelope and nativeComparison is `{value,delta,status:'match'|'different'|'unavailable'}` for the margin template. Static diagnostics return no rows. Server independently resolves/authorizes every record and input. Shared API types freeze the exact nested descriptors before UI integration. No arbitrary browser inputs are accepted.
- All eight table bundles use the same evaluator and existing at-most-500-record chunks. Formula definitions with any finance-restricted dependency are omitted from catalog/definition lists/bundles for that viewer, together with their results and dependent formulas. Direct preview/config requests for those formulas return a generic forbidden response; no expression/AST/dependency names are exposed. The internal restricted quality remains for evaluator propagation, but it is never a substitute for output redaction. Nonmanagers may view permitted formula definitions; management permissions still gate edits.
- Every definition create/update/archive/restore and custom scalar value write takes the same org/table advisory lock before locking definition rows, in deterministic ID order when multiple rows are locked. Add a real concurrent PostgreSQL graph/value test. Definition graph is validated in that transaction; reads use a consistent definition/value snapshot or detect/retry concurrent version changes so a bundle cannot combine incompatible revisions.
- Template identity: nullable immutable `templateKey` on definitions, unique `(org_id,table_id,template_key)` including archived rows. Installer requires explicit `--org-id`, expected organization slug/name assertion and actor profile ID, defaults to dry-run, and executes only with `--apply`. Existing key returns unchanged regardless of edited label/expression/archive state. An unrelated label collision stops. Construct the template through trusted stable source IDs and canonical validation, independent of locale. Target creation is authorized by the user; it is not an all-org migration.

# Factory admission, time and accounting contract

## Data model and states

`RunLedger` owns `runId`, creation/expiry, admittedAttemptCount, malformedDebit, knownSpentMicroUsd, optional inFlightAttemptId, reservedMicroUsd, unknownCostFence and bounded settled attempt IDs. Amounts are finite nonnegative integer micro-USD. Counters are finite nonnegative integers. The combined abuse/admission allowance never exceeds the configured cap. Actual provider spend may exceed a reservation: record overshoot and deny later admission; this is not an invoice ceiling.

`Attempt` owns authoritative UUID, logical decision ID, run ID, dispatch state `not_dispatched|possibly_dispatched|received`, cost status `provider-reported|unknown`, nullable cost and elapsed time. A run has at most one unsettled upstream attempt. Settlement matches the attempt ID, not the current token. A second settlement is a no-op with a bounded duplicate diagnostic. Known success or error cost settles actual spend once. Potential dispatch with unknown cost consumes the attempt and fences the run. Proven pre-dispatch failure releases reserved spend but does not refund the already consumed call count. Expired/revoked tokens cannot create a call, but their admitted attempt can settle. Settled ledger deletion additionally requires authoritative terminal run status plus retained no-remint tombstone; live-run expiry/rotation/revocation never clears cumulative counters. Mint rejects terminal/retired run IDs. Test known settlement → token expiry → sweep/cleanup → same live run remint; the prior debit remains.

Admission reasons are additive typed values `run_busy`, `cost_unknown`, `run_budget`, plus existing 400/401 reasons. Shell maps all denied/non-ok outcomes to its existing advisory fallback, retaining the body receipt. Malformed debit is checked before increment, including after cap exhaustion. Do not expose capability values in logs, files or fixtures.

## Time and HTTP contract

Proxy JSON adds optional `remainingMs`; accept only finite positive integer durations. Reject zero/negative/non-finite/non-integer values before inference, and clamp oversized positive durations to the existing server maximum. Absence preserves general-call timeout. Every controlled hop subtracts local monotonic elapsed; no absolute wall-clock deadline is trusted across hosts. Client transit time and server cancellation latency are recorded as limitations; the caller's independent total timeout still protects the hook.

`handleJevDecideRequest(token, body, {signal?, remainingMs?})` and `jevDecide({...existing, signal?, remainingMs?})` are planned additive signatures. The route begins timing before expensive middleware parsing where feasible and aborts only on genuine request abort or unfinished response close. The signal remains active while reading headers and body, and all listeners/timers are cleaned up. Timeout after possible dispatch is unknown exposure, including failed JSON parsing and disconnected response consumption when no complete bill is available. An HTTP error with a valid cost receipt records that bill.

The guard's semantic budget starts before preparation, is at most 4000ms and must fit inside the unchanged 6000ms hook budget. Direct and proxy curl timeouts use remaining time, not their legacy 20s/25s defaults for a hook call. Missing duration keeps those general defaults. A delayed preparation subprocess must also be bounded. Floor denial is emitted before network and before best-effort logging. Tests measure monotonic time; scheduler noise is reported separately and must not be used to extend the contractual deadline.

## Accounting compatibility and durable source

Preserve caller logical `decisionId`, authoritative proxy `attemptId`, v2 bindings, known zero, requested/resolved models and report quarantine rules. Use one bounded append-only accounting format derived from current v2 envelopes, separate from best-effort `jev-shadow.jsonl` diagnostics. Runner-authoritative source is `${FACTORY_DATA}/jev-accounting/<validated-run-id>.jsonl`; direct shell source is `${FACTORY_OUT_DIR}/jev-accounting.jsonl`. Proxy shell records there are comparison/mirrors only and cannot overwrite runner-authoritative facts. Runner paths derive from the bound run row/token, never arbitrary request paths. Journal contains at most admission plus settlement per admitted attempt, <=16KiB metadata per entry, no prompts/credentials; cap is `2*configuredRunCallCap` records plus bounded reconciliation records. On capacity/write failure deny further auxiliary admission and expose incomplete coverage, never discard unresolved entries. Atomic bounded lock/append/fsync precedes provider dispatch. Settlement append/fsync precedes deleting a temporary result. A failed settlement write retains admitted unknown and the temporary receipt for reconciliation. Never rely on best-effort shadow logging as complete accounting.

Local direct attempts get an admission record before dispatch; proxy admission is authoritative only at the runner. Denied 401/400/429/run_busy/cost_unknown and deterministic floor observations are not provider attempts and do not fabricate unknown bills. A proxy transport timeout with unknown remote admission records an explicit unresolved submission reference; reconcile against runner journal by logical decision identity before counting it as an admitted attempt. Unknown admission stays incomplete, never known zero. Pre-dispatch failures proven unsubmitted have no unknown bill. Known malformed/HTTP-error usage settles a real admitted attempt. Guard may delete temporary `jev-<tag>-result/error.json` only after durable journal settlement or preservation of its unresolved admission; journal outlives guard cleanup and terminal worker output.

Shared shell helper returns `{knownCostUsd,unknownAttemptCount,costCoverage:'complete'|'incomplete',receiptRevision}`. `receiptRevision` is a canonical hash of authoritative admitted/settled identities and dispositions, not wall time. Unknown count covers admitted possibly-dispatched attempts without complete bill; unresolved proxy admission is separately incomplete. `sum_cost_usd` stays numeric known subtotal for compatibility. Add known non-Jev worker costs to unique known Jev costs; when the same Jev result file and journal represent one attempt, count it once. Legacy idless records stay unjoined and cannot prove complete coverage. Preserve existing spec-grounding known subtotal/unknown source fields without pretending its aggregate is one identified attempt.

The concrete transport is `agent/run.sh:emit`, `agent/spec.sh:emit`, `agent/reconcile.sh:emit` → `result.json` → `runner/src/queue.ts:FinishResult`/`parseFinishResult`/`finish`/`finishRunInner` (including restart cancellation result reads) → `budget-reservations.ts:settleRunReservations`. Keep `costUsd` as legacy subtotal; additive qualified fields survive every stage. Runner recomputes/merges against its own authoritative journal, quarantines conflicts and never trusts container coverage to override unresolved runner admissions. Incomplete known subtotal must not settle all reservations as a complete provider-reported run bill. Pass optional coverage to the existing settlement helper and retain unknown/unsettled commitment until authoritative positive reconciliation; do not turn an unknown bill into a token estimate presented as complete. This does not block deterministic floor/baseline fallback or add paid retry.

`stats.ts` must not permanently cache terminal incomplete/in-flight receipt state. Cache only finalized complete coverage at matching revision, or recompute; invalidate its short aggregate cache on journal settlement. Late settlement after revoke/terminal status changes known subtotal/coverage exactly once. Existing report consumes compatible v2 attempt records and continues authoritative precedence, conflict quarantine and cohort separation.

The capability cap applies to container proxy calls. Direct host/idless calls keep their current separate policy and are not run-cap qualified. No secret-bearing direct-container bypass is introduced. Run-bound direct invocation must use the same authoritative ledger or fail closed for that qualified mode.

# Chat evidence and accepted-run contract v1

## Ownership and accepted-run data model

Extend the existing preparation helper without replacing it. `src/lib/assistant/accepted-runs.ts` is the only bounded client lineage store. A binding contains `submissionId`, `runId`, `taskRootId`, nullable `parentRunId`, `origin: user|ui_choice|artifact|ui_followup`, actor/org/agent/session, opaque surface registration owner, captured preparation epoch, monotonic accepted generation, accepted-run controller, page-context revision, creation/expiry time, follow-up count, transport status and final state. No prompt/envelope/tool payload is stored here. The maximum is **256 entries**, expiry **two hours from creation**, oldest first eviction; owner change and surface disposal revoke automatic authority. Sweep at insertion/lookup; no unbounded timer per entry. Actor/org change clears all bindings and pending observation buffers. A→B→A is a new generation even when identifiers return to equal values.

Transport status is `submitted|accepted|rejected|unknown`; UI execution status is `unclaimed|claimed|finished|canceled|invalidated`. Store a final claim keyed by the exact bound run/session, not text/timestamp. A single run has at most one actionable final. Record/claim synchronously before the smoother's async completion; a duplicate cannot schedule a second action batch. Capture the originating run before `chat.runId = null`. A final event for the bound run is acceptance evidence even when its RPC ack is late; late ack may add observation evidence but cannot reset final/cancel state. Unknown/evicted/expired/history-only/legacy run renders normally with no automatic UI authority.

`sendAssistantTurn` receives an optional local binding descriptor and observation sink; it retains existing optional caller ID and return type. Register submission before an externally scheduled final can run; remove/reject the provisional record on definite synchronous rejection. Only authoritative matching gateway ack/event upgrades accepted status. Do not label the local synchronous return as accepted. Unknown acknowledgement preserves the same run ID and blocks replay. Legacy callers remain source-compatible and unjoined, with no implicit automatic-action binding.

The current `scopeEpoch` is preparation-local; do not compare an epoch number from one surface with another or use it as the accepted lifetime. Pair the captured preparation epoch with an opaque sending-surface token. The accepted store owns a separate monotonic invalidation generation and live owner/session reader for that surface. Context notifications still invalidate pending preparation. Only the exact qualified handoff below can preserve an accepted generation across a context revision; every external/unqualified change increments it irreversibly. Component teardown marks the surface dead and unregisters its listeners. Home and Floating may both exist; each accepted binding belongs to the actual sender.

Create an accepted-run-owned AbortController at the local submitted transition; never retain `PendingSubmission.signal` as its lifetime signal. `pendingSubmissions.finish()` aborts preparation even on successful submission and must leave the accepted signal live. Stop captures the exact accepted run from the sending surface, revokes its binding and aborts its controller before `abortChat`, including while the smoother has cleared `chat.runId`. Rejection, terminal failure, expiry, eviction, external invalidation and teardown also revoke the accepted controller. A late ack or preparation cleanup cannot create a new controller for that run.

## Action and callback transition

1. On a final, load and synchronously claim the exact accepted-run binding before clearing chat state or scheduling smoother completion.
2. At callback entry validate unexpired binding, live surface, actor/org/agent/session/accepted generation, cancellation and page-context revision. These checks are local safety gates; actual UI/server tool authorization remains authoritative.
3. Before `waitForTool`, after it resolves, before `executeTool`, after it resolves and before each next action, validate the same ownership. After execution, distinguish unchanged context, the single qualified handoff below, and revoked authority; a handoff never permits another old-batch call. Pass the accepted run's AbortSignal into `executeTool`; extend `waitForTool` with optional signal and preserve its existing signature/default timeout. Abort is cooperative; validity checks decide authority.
4. Execute sequentially. Keep the current `hub.navigate` user-proposal behavior; no automatic navigation is introduced. It remains terminal and forbids follow-up. Do not use `Promise.all` to start multiple side-effecting calls from a batch after the first may change context.
5. Only a qualified local invocation handoff can attribute a changed page context to the admitted action. Stop the old batch, consume that one handoff and capture a fresh preparation binding at its resulting revision for completed results only. Revalidate throughout fresh preparation and at submitted commit. All external/uninstrumented page, location or tool-registry changes, owner/session changes and cancellation send no continuation. Neither a tool result string nor “a tool is running” establishes causality.
6. A valid follow-up carries parent run/root and increments the root's existing five-follow-up bound only on submitted dispatch. Count is stored with bounded lineage, not an unbounded session-only map. It includes context-transition follow-ups. No sixth silent send.
7. An explicit choice/artifact callback carries its `ui_choice`/`artifact` origin separately from a typed user turn and always bypasses the classifier with full context. Pass the exact source message's optional bound run through rendering callbacks. An ephemeral object/row association may link the live final; do not change gateway shared wire types or persist guessed mappings. Unknown source after history reload is a new root, never guessed from nearest text/time. Explicit click does not revive automatic old-page authority.

Stopping a submitted run first marks its local binding canceled, then invokes existing exact-run `abortChat`. Error/aborted events terminalize local automatic authority. Late output may render but cannot execute tools. Any preexisting UI operation already admitted may finish; cancellation cannot retract a completed external effect.

### Narrow local context handoff

`accepted-runs.ts` owns an opaque, nonserializable capability recorded in a private map, at most one per active invocation and bounded by the existing 256-run store. Its record binds exact accepted run, sending surface, accepted generation, invocation identity, current tool registration identity, page-owner lease, prior revision and a single resulting revision. The publication capability expires at invocation settlement, revocation or 30 seconds, whichever is first (also no later than run expiry). Successful publication closes it immediately and records one acknowledgement. That acknowledgement may be consumed only at the immediate guarded post-execution boundary, still before the same time/run expiry and under the unchanged accepted generation, then is destroyed. An unpublished capability cannot survive settlement; neither capability nor acknowledgement can authorize another old-batch call. Expiry forbids continuation without pretending to cancel an already committed effect. One publication and one consumption are allowed. Never serialize it into input/output, analytics, fixtures or a DOM/window event; never trust a caller-supplied ID or arbitrary tool payload. `model-context.ts` passes it only through an optional local execution-context field for the enrolled producer; native WebMCP/dev-console execution has no accepted capability and retains conservative behavior.

The initial and only enrolled production producer is the mounted sandbox's `sandbox.upsert_element`, `sandbox.remove_element` and `sandbox.arrange`. Wire `src/lib/sandbox/tools.ts` to a local acknowledged mutation callback supplied by `src/routes/(app)/sandbox/+page.svelte` at `registerSandboxTools`. After the existing API write settles, await that callback rather than emitting the current unacknowledged `SANDBOX_CHANGED_EVENT` for the same change. The callback passes the invocation capability explicitly into `src/lib/sandbox/host.svelte.ts`'s `load`; successful reload publishes the new canvas summary synchronously with assignment of the corresponding element snapshot. Existing UI load/write calls and the window event carry no capability. Do not infer provenance from event detail, element ID or timing, and do not emit a duplicate unqualified notification for the acknowledged assistant path.

Add an owned page-context lease/update API in `page-context.ts`, retaining `setPageContext` compatibility. The sandbox registers one lease per page lifetime, publishes the initial summary and publishes later host snapshots through that lease; replace its current `$effect(() => setPageContext(canvasSummary(host.elements)))` so every reload does not dispose/recreate the owner or emit a second, causally ambiguous revision. Disposal/location changes remain external invalidations. Host publication supplies the exact lease and opaque capability to the page-context notifier; the accepted store verifies both against the current source registration and prior revision before recording the resulting revision. Every other observer invalidates normally. The pending preparation controller still invalidates on all notifications, including this one.

Validate immediately before snapshot publication and again after the awaited tool returns. A concurrent user navigation, A→B→A, unrelated registration, another host reload, source-tool unregister, Stop or lease/surface/owner change permanently revokes the capability. Reordered, duplicate, late, forged or uninstrumented notifications cannot repair that generation. A failed reload or expired/missing capability yields no handoff/follow-up; preserve the completed write result as evidence and never replay the mutation to obtain context. The runner consumes only the acknowledged resulting revision after the tool settles, excludes every unexecuted old call and sends at most one fresh completed-results continuation within the existing root cap. No general async context propagation, global executing flag or automatic navigation is introduced.

## Route attempt contract

Keep `requestRouteDecision` backward compatible with optional metadata in its options. Home/Floating pass `submissionId` before classifier dispatch, as bounded canonical UUID in `x-minion-run-id`. The route validates the header before feeding current telemetry hashing; missing/invalid header is unjoined, never another actor's authority. Request identity retains server route/request/actor/org.

Add a typed result envelope around the current service: `decision: RouteDecision|null`, and nullable attempt metadata. Expose the richer result through additive `classifyAssistantTurnWithEvidence` and `requestRouteDecisionWithEvidence` helpers in the existing service/client modules; Home/Floating use these helpers. Existing `classifyAssistantTurn` and `requestRouteDecision` wrappers retain their nullable-decision form for other callers. The route response is `{decision,attempt}`; client validation treats missing old-server metadata as unjoined coverage. Existing `RouteDecision.cost` is a legacy compatibility field only; all new cost consumers use the explicit attempt status/value and never interpret a fallback zero as a known bill. An actual attempt has server-generated `attemptId`, nullable submitted UUID, requested model, nullable resolved model, `schemaRevision`, `questionRevision`, actual elapsed milliseconds, server deadline, disposition `ok|timeout|error|invalid`, optional token counts, and `cost: {status: known, usd: finite nonnegative number}|{status: unknown, usd: null}`. Missing key/empty text/disabled is a disabled outcome with **no provider attempt ID**. Client router mode off and explicit callback bypass likewise make no route/provider call.

Compute revisions from canonical ordered public question/schema/gate artifacts; never hash customer text into general analytics. `resolvedModel` must come from actual provider response identity; do not substitute the requested alias. Known zero requires an explicit valid provider-reported zero. Invalid/missing usage preserves unknown. Capture elapsed time in finally/result handling for timeout/non-200/oversized/malformed response, not only success. A bounded valid usage receipt on an HTTP-error/invalid-decision response is preserved before interpreting the decision; missing or unparseable usage stays unknown. Client and server deadlines have separate fields.

Client distinguishes `prepared` from `applied` and `discarded`. A route result may be prepared before context composition but is applied only when that generation commits a local submitted dispatch. A synchronous rejection/cancel/context invalidation produces discarded with bounded reason. `routed|full_fallback|bypass|canceled|invalidated` is the decision disposition; prepared/applied/discarded is its observation phase. A successful server attempt plus discarded client event is not applied routing.

## Observation endpoint and analytics

`POST /api/assistant/decision-events` accepts `{version:1, events:[...]}` only. Require `requireAuth`, actual current `requireCoreCtx`/tenant context and same-origin browser request. Explicitly classify this exact path as authenticated self-only observation in `rbac.service.ts` and its tests: it cannot execute a business action/read another user's data and does not require invented settings/admin permission. `hooks.server.ts` must continue normal auth and must not server-token-exempt this path. There is no page/nav entry. If route-contract inventory covers API routes, add its authenticated self-only entry; otherwise test the real API route inventory and record why the UI manifest is unchanged.

Require `Content-Type: application/json`, `Origin === event.url.origin`, and reject `Sec-Fetch-Site: cross-site` even with a forged matching value. Same-origin browser fetch supplies Origin. For JSON this explicit check is required; framework form-only CSRF protection is insufficient. Use the existing local guard pattern as reference, not a dev-auth bypass. Read the body with a byte cap, not `Content-Length` alone; reject above **16 KiB**, including a stream with missing/lying length, before JSON parsing. Batch maximum **20 events**, no nested arbitrary properties.

Kinds are exactly `decision_prepared`, `decision_applied`, `decision_discarded`, `run_relation`, `transport_submitted`, `transport_accepted`, `transport_unknown`, `task_terminal`. They map to fixed server events `assistant_decision_prepared`, `assistant_decision_applied`, `assistant_decision_discarded`, `assistant_run_relation`, `assistant_transport_submitted`, `assistant_transport_accepted`, `assistant_transport_unknown`, `assistant_task_terminal` respectively; payload cannot choose a PostHog event name. Every event has UUID `eventId` and `submissionId`; optional UUID attempt/root/parent/run IDs; fixed origin/mode/disposition/reason enums; finite bounded scalar revision/size/elapsed fields; loaded-manifest booleans for known IDs only. Task terminal is explicitly a **client observation**, not an independent successful domain receipt. Client values never assert authoritative gateway acceptance beyond what the client observed.

Reject unknown kinds/properties, nested objects, prompt/envelope/tool-output/raw-error fields. Reserved forged actor/org fields, if present, are ignored and overwritten by current server identity; they are never spread into capture properties. Model IDs are bounded public ASCII identifiers ≤160 characters, revisions are SHA-256 hex, UUIDs validated before hashing. Reuse the actual sanitizer count/duration/probability validators for telemetry values; do not widen existing caps. Each event schema enumerates allowed fields per kind, with no generic scalar pass-through. Loaded manifest fields are exactly boolean `loaded_pages`, `loaded_forms`, `loaded_data`, `loaded_brain`, `loaded_changelog`, `loaded_sandbox`, so the flat wire shape preserves the actual selected set without arbitrary arrays. Reasons are an enum (`user_stop`, `owner_changed`, `context_changed`, `expired`, `evicted`, `unmounted`, `transport_rejected`, `ack_unknown`, `router_unavailable`, `overflow`, `network`, `normal`); no free text.

Extend both `fields` and `eventFields` in `observability-context.ts`, including `p_sandbox`; preserve all old probability fields. Keep the real `captureServerEvent` sanitization path. Capture tests mock only the final SDK sink and assert the sanitized payload actually received there. Cost fields support null with explicit status; malformed paired status/value rejects or drops the whole observation rather than converting it to zero.

Extend the existing `rate-limit.ts` additively with atomic weighted charging; existing `checkRateLimit` callers retain default weight one and their behavior. Charge validated batch length under a fixed observation namespace plus server-derived actor+org against **120 events/60 seconds**, before capture. Reject the whole over-budget batch with 429, never half-charge/capture it. The current map has no idle-key eviction: add a bounded namespace in that same module for this endpoint, at most **4,096 actor/org keys**, pruning entries whose last charged timestamp is at least 60 seconds old on access/admission. At capacity after pruning, reject an unseen key with 429 rather than evicting an active budget. Denied batches do not extend idle lifetime or add timestamps; each key stores at most 120 charged event timestamps (or equivalent bounded weighted records). No timer, new limiter service or lifecycle change to unrelated callers. This is a per-process guarantee, not fleet-global quota enforcement. Tests use a controlled clock to prove atomic charging, expiry/cardinality and default-caller compatibility.

Client `decision-events.ts` owns at most **20 memory-only events**. Flush only under the owner captured when queued; attach abort controller/generation to an in-flight flush, drop it on owner change and never replay it under a new owner. A prior request already admitted by the server remains under its resolved identity. Failure/overflow drops are reflected in local fixture coverage counters; no infinite retry or localStorage payloads. UUID event identity enables analysis dedupe, not exactly-once analytics delivery. Do not upload content as a compensation for missing telemetry.

## A/F evidence handoff

A exports the same validated event shape through its test adapter. F's runner writes authoritative append-only fixture observation/receipt files; analytics is best effort and is never substituted for these receipts. F deduplicates event IDs, quarantines conflicting duplicates, joins exact parent/root keys and reports missing events/expected action receipts. Neither package infers free-text lineage. Server identity and fixture identity are labeled separately. Existing production authorization is exercised in A endpoint/tool tests, not certified by F's synthetic persona.

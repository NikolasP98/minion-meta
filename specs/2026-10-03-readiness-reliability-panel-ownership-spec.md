# Remaining reliability consumers

## 0. Product

The accepted eight-resource HC024 candidate does not own plugin health, historical insights, skill statistics, credential health or architecture polling. Source at Hub eb6867db: `state/async.svelte.ts:66-87` publishes any completed request and its finally flag, including after reset; exactly four source createAsyncResource consumers are reliability/{plugin-health,insights,skill-stats,credential-health}. The first ignores its serverId and uses ambient Gateway transport. ArchitectureGraph.svelte:139-151 directly publishes concurrent fetch completions. PluginHealthPanel.svelte:90-106 adds a live sample to snapshot counts without an event watermark. The recent-events getter returns raw feed data until the reset effect. AgentDashboard.svelte:79,118 labels a global filtered summary as this agent's errors today, or zero when no owned summary exists.

## AS-IS

Only plugin health and insights have production component callers. Skill-statistics and credential-health factories currently have no non-test UI caller; this slice qualifies their dormant state/API contracts, not invented panels. Mounted UI proof covers PluginHealthPanel, InsightsPanel and ArchitectureGraph only.

HS033: insights authorizes by global-admin/host link without reliability:view, while both metrics GETs accept tenant context and arbitrary serverId without current reliability capability and target authority.

HS032: skill-stats.service.ts:157-158 returns count(*) beside avg(duration_ms), where SQL ignores NULL duration. skill-stats.svelte.ts:64-82 weights the average by all executions, including missing durations. Even entire missing-duration groups influence later denominators. A correct measured-duration mean requires its own sample count.

## HTTP authority and work budgets

Every insights, skill-stats and credential-health GET requires a real canonical user, current active organization membership, and freshly resolved reliability:view. Do not reuse stale page-data permissions or a cached capability result. Resolve the requested canonical gateway by exact UUID or its unique legacy bridge directly from canonical PG; require its org_id to equal the active organization and an ordinary actor's current user_gateway link. A canonical global admin may omit the user link only after fresh canonical admin status and active organization membership are proven; admin never bypasses target organization ownership. Missing, ambiguous, remapped or foreign targets deny before data/cache access. No first-host fallback. Skill statistics query canonical PG by the resolved gateway UUID and organization RLS; a canonical-only gateway with no legacy bridge remains valid. Only insights and credential-health additionally verify that their Turso telemetry server belongs to the exact canonical legacy bridge, then read its stored telemetry tenant. For those two telemetry routes a missing bridge is unavailable, never a fallback to the caller tenant. Architecture keeps its existing capability gate and must also reject removed membership. HTTP read availability never depends on a live Gateway socket.

Use a focused authorized-read context for all three routes. Require serverId, bound it to256 characters, and reject duplicate/unknown query parameters. `from` and `to` are finite nonnegative safe-integer epoch milliseconds, from<=to, to<=serverNow+60seconds. Default to last7days; accept up to90days and reject a wider custom range with a visible range error. `limit` is an integer1..2000 (default200 skill rows,100 snapshots); summary is exactly true/false; skillName is at most256 characters. Valid explicit zero timestamps remain valid values rather than falsey absence. Preserve the insights fixed24hour/previous7day comparisons and equal prior-window semantics within these budgets.

Every DB read has an admission budget and finite materialization bound. Skill PG reads run in withOrgCore with transaction-local statement_timeout3seconds and at most2001 grouped rows (2001 means reject, never truncated success); raw rows use their admitted limit. Turso insight calculations must use a scoped, indexed bounded input relation: exact telemetry tenant+server+time window, materialized at most100001 events for each required window, where the sentinel beyond100000 rejects the entire result before computing totals. Every aggregate derives only from this admitted complete relation; LIMIT on a final grouped result alone is insufficient. Capture all current, prior and fixed-baseline windows in one owned read transaction/snapshot, materialize each bounded relation once within that snapshot, and compute every total/trend/action from those admitted rows. A later insert or delete cannot alter another metric or cap decision in that observation. Do not rely on an id high-water unless an append-only/no-delete invariant is separately proved; this slice uses an actual consistent read snapshot. Add/verify the supporting tenant/server/occurred_at index through the owning schema/migration path. Validate limits against real EXPLAIN and a cap+1 fixture. Credential snapshots require bounded SQL-side blob size checks before transferring snapshotJson and at most the admitted row limit; oversized selected snapshots fail rather than disappear. Server output caps are2000 entities,5000 series/link rows and8MiB UTF-8 JSON; before materializing JSON, select bounded individual fields/blobs and reject aggregate cardinality sentinels. Do not silently truncate totals.

The HTTP observation deadline is15seconds. Scoped remote libSQL HTTP reads use an AbortSignal-aware fetch and close their owned read client/stream on completion/timeout; a timeout is not represented as proof that a remote database query was cancelled. Admit at most4 active reliability reads per server process and1 per canonical actor/target, no unbounded queue; saturation returns retryable503. Hold the admission slot until the underlying database work settles or its owned execution handle is confirmed closed, even if HTTP already timed out. Local file-backed long-running reads use an owned worker/connection whose termination is acknowledged before releasing the slot. No Promise.race that frees capacity while work continues. Cache authority is checked freshly before lookup; cache keys include exact authorized target/telemetry scope and normalized query, and no failure is cached as empty.

Client HTTP reads consume Response.body incrementally with a decoded-byte counter, cancel at8MiB+1, then decode/parse once. Content-Length may reject early but is never trusted as the sole bound; absent or compressed length still has decoded-byte enforcement. Fetch and body read use the captured owner AbortSignal and15second bound. Plugin RPC uses the transport's bounded gateway frame and the GW024 broker's4MiB response cap, then its endpoint decoder; this spec never claims a post-JSON object check bounded received bytes. Architecture shares the HTTP body bound and the same server process/actor-target observation admission limits. Its PG/Turso probes retain slots until the underlying owned work settles or handle closure is acknowledged, including after a per-probe/HTTP timeout; repeated polling cannot accumulate continuing probes. Its HTTP/WS probes close or abort their owned handles on deadline and disposal. Preserve current per-probe deadline values, but replace Promise.race-only disposal and raw database/provider exception strings with fixed safe status codes. Treat architecture as an explicit fourth route under these work budgets while retaining its existing global-architecture authorization shape.

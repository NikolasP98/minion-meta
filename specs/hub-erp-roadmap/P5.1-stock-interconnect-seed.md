**Repo:** minion_hub (`dev`). Builds on shipped P5 (`f6dc6ef2` core, `5d7780d4` UI, `a22f679a` gateway). P5 recon 2026-07-03: schema/service/API/UI/reorder-alerts/connections/gateway all EXIST — this phase adds the cross-module layer the user asked for and seeds real FACES data.

**Recon facts that constrain design:**
- Invoices are 100% SUSII-sync-only; `upsertInvoicesBatch` delete-replaces `fin_invoice_items` on every sync (`finance.service.ts:168`). → NEVER write fin_* rows from stock; the invoice↔stock link lives in `stk_entries.metadata` (`{source:'invoice', invoiceId, providerRef}`).
- Catalog triangle already exists: `sched_event_types.product_id → fin_products ← stk_items.fin_product_id`. The consumption map completes it: **fin_product (service/product sold) → stk_items consumed**.
- `stk_ledger` append-only; bins rebuildable; `submitEntry` is the only ledger writer (FOR UPDATE locking). Seed goes through the same invariants.
- FACES org_id `21e0601b-f632-43fd-8414-d644af4271f4` (resolve by slug `faces-sculptors` at runtime in script; don't hardcode in app code).
- Hub worktree carries UNRELATED WIP (custom-roles session: `rbac.service.*`, `api/roles/`, `RbacRolesSection`, `settings/team`, `org_roles` migration). DO NOT touch or commit those files.

## D1 — Migration `supabase/migrations/<ts>_stock_consumption.sql`

```
stk_consumption (
  id uuid pk default gen_random_uuid(),
  org_id text not null,
  fin_product_id uuid not null,        -- the sold service/product (fin_products)
  item_id uuid not null,               -- stk_items consumed
  qty_per_unit numeric not null,       -- consumed per 1 unit sold/performed
  note text,
  created_at/updated_at timestamptz default now(),
  unique(org_id, fin_product_id, item_id)
)
```
org_guc RLS + `app_ledger` grants exactly like `20260702130000_stock.sql`. Orchestrator applies to prod; agent writes file + Drizzle table in `pg-schema/stock.ts`.

## D2 — Backend (W1)

1. `stock.service.ts` additions (same conventions):
   - `listConsumption(ctx, {finProductId?, itemId?})` — joined names (product name, item name/code/uom).
   - `setConsumption(ctx, {finProductId, itemId, qtyPerUnit, note?})` upsert; `deleteConsumption(ctx, id)`.
   - `buildInvoiceIssuePreview(ctx, invoiceId, warehouseId)` — read `fin_invoice_items` for the invoice, join `stk_consumption` on product_id, aggregate to lines `{itemId, qty: sum(inv_qty*qty_per_unit)}`; also direct-match invoice items whose product maps to a `stk_items.fin_product_id` with `is_stock_item` (retail products sell 1:1 even without a mapping row — dedupe if both paths hit). Returns lines + unmatched invoice items (name-only report).
   - `createIssueFromInvoice(ctx, {invoiceId, warehouseId, lines, submit, actor})` — creates `stk_entries` type `issue` with metadata `{source:'invoice', invoiceId, providerRef}`, lines as given (UI may edit preview), optional immediate `submitEntry`. Guard: refuse duplicate — an existing non-cancelled entry with same `metadata.invoiceId` → 409-style StockError.
2. API: `GET/POST /api/stock/consumption`, `PATCH/DELETE /api/stock/consumption/[id]` (central write-gate covers RBAC; add `isModuleEnabled` 404 like siblings). `POST /api/stock/entries/from-invoice` `{invoiceId, warehouseId, lines?, submit?, preview?}` — `preview:true` returns computed lines only (confirm-before-write contract).
3. Gateway surface (agent-native day-one rule): `query/stock` gains mode `consumption`; new `POST /api/gateway/actions/stock-issue-from-invoice` (preview/confirm pattern, capability `stock:create`) wrapping the same service fns. Register in the same places as `stock-entry-create`.
4. Tests: preview aggregation (mapping × qty, 1:1 retail fallback, dedupe, unmatched report), duplicate-invoice guard, consumption upsert uniqueness. Route-level tests optional (match existing depth).

## D4 — Seed script (W3)

`scripts/seed-stock-faces.ts` (bun + drizzle-postgres; read `SUPABASE_DB_URL` from `.env.local`/process.env like existing scripts; resolve org by slug from Turso `organizations` OR accept `--org <id>` flag — flag is fine, keep it lazy). Input: normalized JSON path arg (produced from the 4 root CSVs; do NOT commit the JSON).

Steps (idempotent — abort if `stk_items` non-empty for org unless `--force`):
1. Warehouse `MAIN` / "Almacén Principal".
2. Items: 24 stock products from catalog (`Producto a la venta`/`Producto interno`) ∪ levels ∪ movement-only (`HA Opera II (Caja)`). code = source `src_id` (e.g. `1247`), uom `Unidad`, item_group = familia, reorder_level = min, reorder_qty = max>min ? max−min : null, `fin_product_id` matched by normalized name (lower/strip accents) against org's fin_products — leave null on no match.
3. History replay: movements sorted by ts → group by (date, sign+type) → `stk_entries` (type: qty>0 → `receipt`, qty<0 → `issue`; `Manual` corrections keep those types too — boring) + lines; ledger rows with running qty_after and moving-avg valuation using rates: receipts at item avg_cost (export(1)/catalog `Precio medio`), issues at bin rate. Write entries as `submitted` with posted_at = movement ts, note = source type + comment (comment carries SUSII invoice #). Insert ledger/bins directly with the pure fns from `stock.logic.ts` (import them) — do NOT call submitEntry 1578× against prod; same math, one script tx per batch.
4. Reconciliation: computed final ≠ export(1) `units` → one final `adjustment` entry per direction dated 2026-07-01, note "Reconciliación import CSV", bringing bins exactly to export(1) (18 items; items absent from export(1) reconcile to last movement stock_after, floor 0).
5. Consumption mappings (LOW-CONFIDENCE heuristics, user-editable later unless explicitly confirmed): fin_products whose name contains a stock item's product token → mapping. Rules: names containing `Opera I/II/III/IV`→ matching `HA Opera N (Caja)` qty 1; `Saypha Volume Plus`/`Saypha Volume`/`Saypha Filler`→ matching caja qty 1; `Toxina`/`Botox`→ `Toxina Botulinica (units)` qty 30 (source system's Consume hint); `NCTF`→ NCTF qty 1; `Hialuronidasa` service→ Hialuronidasa item qty **10 mL per procedure**, with the item configured as **15 mL per stocked vial (`Unidad`)**; retail (Dermaquench, Lifting B, Lip Defense, Watershield, Sensiclean, FAJA-*) 1:1 via fin_product_id (no mapping row needed). Print a table of what was seeded.
6. Verify + print: per-item computed bin qty vs export(1), ledger row count, entry count, mapping count. Non-zero exit on mismatch.

## Design

Keep actual authenticated identity for attribution, record ownership and personal preferences. Add request-scoped effective authority keyed to exact actual profile/organization and replace the evaluated role set with one selected role. Effective platform role is user, closing legacy admin shortcuts. Reuse the canonical capability builder; never create a second permission engine or put simulated rows into the real-member cache.

Session mode is durable and keyed by verified GoTrue session ID. Fresh server admission verifies current membership, actual owner/admin eligibility, role existence and target capability containment, including page/section exceptions, record scope and field levels. Browser generation stamps reject stale new writes across mode changes. A request already admitted before a transition may complete under its captured generation; it is never falsely reported cancelled. The initiating UI waits for its tracked pending commands before Apply, and mode-change broadcast retires/reloads other tabs.

## Alternatives

Durable server session state is selected over signed-cookie state (other tabs retain stale cookies and immediate invalidation needs another store) and tab-local state (direct requests and tabs can bypass the selected mode). One bounded session-row read per authenticated request is the correctness cost; reuse the existing pool, do not add a connection per feature. Verified browser requests load fresh actual capabilities once per admission and share them through request scope; independent jobs retain the existing cache path. This prevents policy edits from leaving ordinary browser sessions on stale role grants. Read/write failures fail closed without restoring actual-admin actions. No new external service is introduced.

## Detailed Implementation Plan

### Concrete admission, comparison and transport decisions

- Session ID must be a UUID from verified GoTrue `session_id`; every verified-session browser request (absent/off/active mode alike) additionally checks the corresponding `auth.sessions` row/user_id and not_after. The FK to auth.sessions cascades logout/revocation deletion; a missing/revoked/expired auth session rejects the request with 401 before treating an absent simulation row as off. A still-signed access token never restores actual authority after cascade. Missing/malformed session ID cannot start or retain simulation. Unverified/dev/server-token identities have no simulation admission. No row means off with generation `00000000-0000-0000-0000-000000000000`. First Apply inserts an off row with that generation (`ON CONFLICT DO NOTHING`), then SELECT FOR UPDATE and compares. All transitions serialize on the row. Start requires off and a fresh eligible target; both transitions replace generation with a random UUID. Active lifetime is 2 hours from start. Expired/deleted-role/revoked-authority mode retains its selected key/generation but supplies empty capabilities until Finish. An authenticated actor/session can Finish even after membership loss; ordinary organization requests still fail membership. Organization mismatch atomically clears active mode and rotates generation before admitting a new org; it never reapplies the role there. Store `return_to text` at Start after local-URL normalization; Finish revalidates that stored URL before fallback. No client-supplied actor/session/org is accepted.
- Strict fresh catalog reads use canonical SQL, not `listRoleCatalog`'s current fail-soft PostgREST projection. Actual member roles use `resolveMemberRoleKeys`. Eligibility requires actual owner/admin organization role or platform admin with current org membership. A non-owner cannot choose owner. Selected rank may not exceed actual rank ceiling (platform admin ceiling is admin unless actual owner). Compare every module and registered subresource plus every existing rule key through canonical `buildCapabilities`: selected actions imply real actions; selected unrestricted records require real unrestricted records; selected field level may not exceed real. Additionally compare every static native route and every live alias/page using canonical page→section→route evaluation and module floors; every selected allowed destination must be allowed to the actual actor. Platform admin actual authority uses its existing full-access semantics. Catalog/projection failure is a 503, never an incomplete list or admin fallback. Recompute at Apply and on each active request; role/policy changes can invalidate mode.
- Create `src/lib/services/role-simulation-client.ts`, install its owner-scoped global fetch wrapper from `(app)/+layout.svelte` before interactions, restore on teardown. It stamps every same-origin mutation (including existing raw fetch), tracks pending mutation promises, and retires captured read responses after generation change. Both active and post-transition off rows require the current header; missing/stale is 409. Initial never-transitioned off mode accepts missing headers for compatibility. Exempt only authentication/session control endpoints and the transition endpoint's own strict generation body; server callbacks without the matching verified browser session remain their separate credential domain. Native form submit capture adds a hidden generation field; server admission accepts that field only for form content types, never query/cookie authority. SvelteKit server internal fetch propagates request generation from the server context if needed.
- Apply/Finish use `tryUseActions()` pending counts and unresolved `attentionRequired` before full reload; wait for the wrapper's pending writes and 500ms quiet save interval. Dispatch a cancelable beforeunload event to reuse the existing Settings dirty signal; if prevented, leave mode unchanged and ask the user to save/discard through the existing editor. Do not change authority first and then ask to discard. New mutations are paused during the final transition request; do not label an admitted write cancelled. BroadcastChannel plus storage event announces changed generation; focus/pageshow revalidate session mode if either transport is unavailable. Retire gateway/query state and replace the document after success; failed transitions keep current mode and draft. Requests already admitted may finish with captured authority; failed/stale UI reads cannot publish into a newer generation.
- Audit refs are UUIDs: simulation transitions use new generation; policy target refs use deterministic UUID derived from SHA-256 of canonical org/target, with original stable target stored in changes. Never put session IDs in audit fields. Modify `withOrgCoreTransaction` capture/restoration for both new simulation GUCs as well as setup, preventing nested scope metadata leakage. Nullable simulation metadata inherits transaction GUCs on ordinary domain audit writes; transition audit explicitly names actual actor.

## Canonical record-policy refinement

The D2 implementation closes formerly unprotected own-record mutations for both selected roles and fresh ordinary browser roles through the same record predicate/parent-lock helpers. This intentionally tightens ordinary if-owner writes that previously checked only organization. Actual platform administrators keep their ordinary bypass; selected authority always takes precedence, even for an actual administrator. Independent jobs and anonymous booking paths without a matching verified browser scope retain their existing contracts. CRM prefill and shared party read projections apply canonical ownership and field masking; unrelated module permissions do not become blanket party-access alternatives. Only the existing customer/supplier consumers (POS, scheduling, stock, finance, sales, support and memberships) retain shared-spine access.
